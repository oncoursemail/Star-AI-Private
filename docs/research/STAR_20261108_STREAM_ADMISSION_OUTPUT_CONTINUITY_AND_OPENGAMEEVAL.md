# Star AI — verified streaming-output admission and game-building intelligence
**Research and implementation: 2026-11-08.** Stacked after draft PR #1079; all new runtime behavior OFF by default.

## Concrete infrastructure change
Current OBS integration verifies a pinned process/socket and rejects accepted QoS data after 750 ms. But a stream can stop or reconnect **within** that window without the OBS PID, listener, or socket changing. In that interval, an ordinary speech-admission decision could still rely on an earlier normal profile.

`ObsLoopbackLiveHost(verify_output_at_admission=True)` closes that narrow observation-to-decision gap *when explicitly enabled by the trusted host*: an authenticated, read-only OBS WebSocket v5 `GetStreamStatus` request is made at an optional commentary/workload admission boundary after healthy paired QoS has been accepted. It verifies active, nonreconnecting output, bounded integer counters and monotonic output duration, delivered frames and dropped frames; a changed OBS process/socket, malformed status, unexpected event, reversed counters, request failure or expired paired evidence revokes the current epoch. The status-only read **never extends** the deadline of an earlier full paired OBS+game/GPU/voice sample. Existing default behavior and absence of any OBS write requests are preserved.

**Important limitations:** status polling has finite transport/OS overhead and is inappropriate for game-render callbacks or per-audio-frame scheduling. It cannot prove there was never a transient output transition between reads, and it is not authorization to start or continue broadcasting. A private, nonbroadcast recording cannot yield live-network stream-loss evidence; that must remain distinct. No model parameters, inference speed, gameplay skill or human-level abilities were changed.

## New research verified
**OpenGameEval**, published October 1, 2026, reports tests of 13 models on 84 curated Roblox Studio tasks. The best model achieved **51.7% single-attempt success**, but only **39.4% succeeded on every one of five attempts**. Consistent inspection before editing correlated with an additional **13.4 percentage points** pass rate on scene-only tasks and **9.8 points** on script-only tasks in a controlled comparison. These are published benchmark results, **not Star AI scores**. Source: https://arxiv.org/abs/2610.02563 and https://github.com/Roblox/open-game-eval

**Implication for Star game creation:** prioritize running the public test suite on a separately controlled Studio machine with exact scenario, place version, tool budget and seed receipts. Measure: task pass@1, pass^5 consistency, number of inspected target/dependency objects, edit-before-inspection violations, playtest result, wall-clock budget, and regressions against unrelated content. Star already has a host-signed pre-edit inspection gate; connect its independent receipts to the benchmark and verify actual multi-attempt success instead of counting model self-critique as progress. Respect licenses and avoid using held-out evaluation cases as training data.

**Roblox Studio MCP** has a built-in officially supported tool server and playtest automation, according to Roblox's March 5 and April 15, 2026 announcements. Prefer the built-in authenticated interface rather than installing extra third-party Studio plugins merely to replay a benchmark; keep source edits and game launches independently approved by the host. Sources: https://devforum.roblox.com/t/assistant-updates-studio-built-in-mcp-server-and-playtest-automation/4474643 and https://about.roblox.com/newsroom/2026/04/roblox-studio-going-agentic

**OBS WebSocket v5** supports authenticated, read-only stats requests and output-state changes. This patch uses those existing protocol surfaces; see https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md

## Highest-leverage VTuber + general-intelligence next steps
1. **Real Windows read-only rehearsal:** pin OBS PID, socket and observation epoch, record status-check round-trip p50/p95/p99, and prove revocation during actual output stop/restart **without starting a stream from Star's code**. Compare OBS render time, game FPS, VRAM pressure, speech admission p95 and first-audible PCM. Test private recording separately; no public broadcast without explicit owner action.
2. **Fast reactive / slow planning split:** handle controls and time-sensitive game cues with a small controller and strict input freshness; queue deep tactical planning, chat summaries, long-term memory indexing, model experiments and art builds behind resource budgets. Measure actual game outcomes on hidden scenarios, not invented wins.
3. **Natural VTuber social agent:** ground commentary in witnessed moments, maintain conversational silence, permit interruption before audible speech, synchronize emotion tags with avatar movements and captions, and keep stable social memory with uncertainty, consent, privacy controls, and clear AI identity. Evaluate speech start latency, interruption-to-silence latency, irrelevant-commentary rate and perceived authenticity in blind trials.
4. **Learning to build games:** benchmark edit quality with OpenGameEval and owner-curated private Roblox game tasks, enforce inspection before edit, run Luau/Studio tests, compare independently verified outcomes, and promote only passing artifacts. Avoid claiming continuous self-improvement just because code was generated.
5. **Model-speed experiment matrix:** run same prompts/game snapshots with different prompt cache settings, quantizations, speculative decoding and CPU/GPU speech splits on the actual RTX 4060, recording VRAM, latency and accuracy together. Revert settings if FPS or voice p95 regresses.

## Verification/rollout gates
Offline deterministic tests cover active stream, inactive stream, reconnecting output, counter reset, unexpected event, wrong correlation ID, failed OBS read and missing counter. Tests use fake sockets; no real OBS communication occurs. New output checks are **disabled by default**, do not start OBS or streams, and cannot authorize game input, speech, or network action. Before enabling, benchmark on the owner's Windows host; only ship after independent code review and full CI. Draft branch does not change production `main`.
