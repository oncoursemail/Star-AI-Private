# STAR AI — Native audible evidence, game/voice latency and generalist intelligence
**Research and implementation date:** 9 November 2026 (America/Chicago)
**Scope:** Opt-in host-side audio evidence bridge; RTX 4060 gaming/VTuber acceptance research. Not a production deployment.

## Shipped on this branch

`star/stream_audible_turn_evidence.py` introduces `AudibleTurnEvidenceAssembler`. It addresses a missing trust boundary in #1084's `LongSessionVoiceHealth`: a speech model emitting text or a PCM queue accepting data does **not** mean an audience heard Star speak. The new adapter requires three independently supplied, matching, monotonic-clock observations before feeding the voice-health monitor:

1. A **host-owned** `SpeechRequestWitness` fixes request start, native output epoch, scene epoch and opaque turn ID before TTS begins.
2. A `DeviceAudibleWitness` is supplied only after a separate output-device/loopback observer detects sound for that exact native epoch. It is **not** legal to substitute “PCM queued”, “TTS complete” or an app callback here. The first-audible latency is derived from request and loopback timestamps; the reviewer cannot supply its own claimed low latency.
3. A `CompletedVoiceReview` binds the same turn and epoch to a separately observed end of audible output and an independent quality evaluation (voice continuity, grounding, repetition, interruption). Review observation must be later than device callback observation and within a five-second ingestion window. Scene changes, stale/overlong output, duplicate receipts, changed sessions, overlapping flights and backward clocks reject evidence.

Only after all three match does the adapter emit `ReviewedVoiceTurn` to the existing long-session monitor. Previously complete health results must never be reused across native output sessions. A new session requires a freshly re-armed, empty voice-health guard, and a session ID cannot be reused on the same adapter. Session counters now reset when the guard is re-armed. The default state remains OFF. No speech text, audio, microphone capture, screenshots, viewer IDs, game state, OBS tokens or private paths enter this module.

**Important evidence limitation:** the Python module cannot independently verify `device_loopback_confirmed` or `reviewer_confirmed`. Those flags are host **attestations**, not signatures or cryptographic proof. The native host must keep its observer, credentials and timing separate from Star's LLM and untrusted viewer chat. This branch does not implement WASAPI capture, voice transcription, new TTS or a broadcast action. The audio observer must ensure the sound belongs to Star, not a game/Discord/browser mixer; Windows system-mix loopback alone is not source attribution.

## Independent research (measured externally, NOT gains claimed for Star)

**Physical audio evidence.** Microsoft's [WASAPI Loopback Recording](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording) documentation describes capturing output from render endpoints and notes that the capture can include the **system mix**. Do not claim source-isolated Star speech from a system-wide loopback trigger. On Windows, the intended adapter should use either a dedicated Star voice endpoint or a separately pinned process/output session, check OS process identity, use capture-packet timestamps where available, calibrate output latency, and reject uncertain association. NAudio's [WasapiRecorder loopback documentation](https://naudio.github.io/NAudio/docs/WasapiRecorder.html) describes a practical Windows capture API whose buffers carry device and clock positions. This design is documentation only; no Windows audio driver is installed by this PR.

**Human-like conversation is selective, not nonstop.** The [Proact-VL paper (3 March 2026)](https://arxiv.org/abs/2603.03447) explicitly studies real-time gaming companions deciding **when** to speak. The [Full-Duplex-Bench](https://github.com/DanielLin94144/Full-Duplex-Bench) research evaluates pauses, backchannels, interruptions, output latency, and overlaps; v3 added complex spoken tool-use and disfluencies in April/May 2026. Star should measure silent decisions, grounded appropriate timing, scene-reactive emotions and interruptions alongside waveform latency. A faster voice is worse if she interrupts or comments on an obsolete game event. The [HiThink Turn preprint (28 September 2026)](https://arxiv.org/abs/2609.34096) is a candidate for *research* on intent-aware overlap decisions, not installed model weights.

**Game intelligence must respect clocks.** [Gym-Anything-RT (27 October 2026)](https://github.com/gym-anything/gym-anything-rt) provides matched live/paused minigame configurations and demonstrates that paused, deliberative model success cannot substitute for genuine live reaction reliability. Star should separately evaluate time-to-observation, local reaction controller deadline miss, control acknowledgment, real-time recovery, and held-out unseen game-mechanic wins. The verified action pipeline must remain owner-authorized and game-rule compliant. Existing `game_live_clock_benchmark` and `game_skill_gate` can supply this independent evidence; this PR does not duplicate them.

**Generalist game building.** [GameDevBench (ICML 2026)](https://github.com/waynchi/gamedevbench) tests visual game-engine tasks; [Roblox OpenGameEval (October 2026)](https://github.com/Roblox/open-game-eval) tests executable Roblox Studio tasks. The right next integration is: inspect scene first, plan under owner-granted scope, produce isolated changes, run deterministic playtests, compare frame/video output to specifications, repair and rerun. Separate verified facts/skills from viewer text, hypothesis, and style feedback. No self-scored claim counts as a successful game build.

**RTX 4060 8 GB stream-speed research.** The exact bottleneck is concurrent GPU occupancy (game + OBS encoder/render + local inference + avatar animation) and CPU speech generation, not a stand-alone tokens/second headline. Compare small fully resident quantized models at Q4/Q5, 4K/8K/16K contexts, f16 vs q8/q4 KV cache, prompt caching, small speculative draft depths and a CPU-only TTS route **one variable at a time**. [llama.cpp](https://github.com/ggml-org/llama.cpp) supplies real implementations; public third-party 4060 Ti/2060 results cannot be treated as Star's RTX 4060 performance. Record TTFT, **device audible first-response latency**, OBS missed render/encoder frames, game p95 frame time, CPU/GPU utilization, peak VRAM, win/recovery rates and correctness on held-out Roblox/general-knowledge cases. Accept a new route only if quality and smooth gameplay are noninferior, not merely if decoding is faster.

## Concrete integration contract and security boundaries

- Trusted Windows host owns one `LongSessionVoiceHealth` and one `AudibleTurnEvidenceAssembler`. The host enables a fresh voice guard, then the adapter with a unique session ID, only after operator opt-in.
- All witness timestamps share a high-resolution monotonic clock. The request event is captured before TTS; native output must be observed through loopback and associated with the same output epoch; completion/review must be independently corroborated.
- Native host retains audio only in an explicitly consented, local, short-lived rehearsal. Adapter holds *no* PCM or transcript. Do not let the model fabricate witness IDs, native event times, quality verdicts, games played or viewer conversations.
- Lost native callback, ambiguous source mixing, interrupted stream, scene mismatch, outdated timer, conflicting IDs or review provenance fault the session. A failed receipt does **not** authorize “best effort” optional commentary.
- `LongSessionVoiceHealth` already preserves essential viewer questions, owner interruptions and danger reactions through separate admission controls; additional quality checks must not suppress emergency stop. Playback STOP/FLUSH and OS acknowledgment remain owned by the existing native PCM bridge.
- Do not run this adapter on the real-time audio callback thread: keep it asynchronous on the trusted host while recording monotonic timestamps at the source.

## Private nonbroadcast acceptance experiment (not run here)

1. **Prepare** a dedicated audio output path, pin output-device and OBS process identities, and prevent any public stream. Record ten idle seconds to prove game/Discord audio cannot masquerade as Star's voice. Ingest no personal viewer data.
2. **A/B 15–30-minute rehearsal** using the *same prerecorded game event sequence* and owner-approved randomization. Compare #1084's independent host-review-only baseline with the physically joined audible review. Collect at least eight baseline and eight later completed turns, including deliberately long answers and pauses.
3. **Adversarial cases:** no actual audible PCM, queued-but-muted audio, OBS/TTS restart, stale >5 s callback, wrong output epoch, wrong scene, duplicate/reordered review, clock rollback, interrupted output, simultaneous game+speech, device mix containing somebody else's voice. Every missing/false witness must fail closed.
4. **Measured outcomes:** zero accepted turns without a physical Star-attributed audible receipt, zero accepted stale/replayed observations, p50/p95 first *audible* latency, p95 STOP/FLUSH response, optional false suppression rate, human independent naturalness/grounding ratings, p95 game frametime, OBS skipped frame counts, and VRAM/RAM.
5. **Decision:** do not enable on live public streams until independent Windows pilot, GitHub CI, no priority-interrupt regression, demonstrably valid process/device provenance and owner sign-off. A green offline unit test proves schema/coordination only; it cannot prove hardware audibility, speech naturalness, or faster inference.

## Longer-term build priorities (not implemented on this branch)

1. Native per-process/dedicated-device WASAPI observer with clock calibration, strictly local ephemeral capture and objective no-sound rejection.
2. Real-time gameplay controller trained/evaluated on matched live/paused unseen mechanics with deadline-aware outcome receipts; never depend on speech LLM for per-frame input.
3. Two-tier memory: verified recent events for conversational context plus independently sourced long-term skill and factual summaries. Clear aging/uncertainty/consent rules.
4. Separate CPU low-latency dialog, constrained local reaction model and asynchronously scheduled deep planner/researcher, measured end-to-end under OBS/VRAM competition.
5. Owner-authorized self-play Roblox Studio lab and game creation with executable playtests, visual critique, rollback, release governance and independently held-out quality checks.
6. Human-feeling expressive timing: coherent character interests, consistent voice, lip-sync/gaze/gestures, occasional silence and humor grounded in observed events. Explicitly identify Star as an AI; do not invent human memories, consciousness, or parasocial intimacy.

**Verification statement:** this branch supplies a deterministic offline *joining mechanism*, not a working native Windows microphone or listener, no game-playing policy improvement, no AI model retraining, and no measurable GPU inference speedup. Hardware/audio/gameplay milestones must be independently tested.
