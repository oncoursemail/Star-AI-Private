# STAR: host-measured performance, game intelligence and natural VTuber roadmap

**Research snapshot:** October 25, 2026. **Status:** host-callback capture contract and offline tests implemented; no live gameplay, synthetic voice, real latency or streaming improvement measured in this patch. This document is an engineering decision record, not proof of increased foundation-model intelligence.

## The important distinction

More prompts, skills and advisory classes do not by themselves make Star intelligent or responsive. Star needs a **closed, measurable loop** that connects a trusted observation to a decision, a permitted action, an independently verified outcome, a retrievable skill, and a held-out test. She separately needs natural turn timing tied to **what the audience actually heard**, rather than what the language model said it would generate.

The existing STAR stack has `stream_stage`, `stream_director`, `stream_turntaking`, `stream_qos`, `game_action_gate`, `active_practice`, `gameplay_skill_bank` and an advisory offline `stream_realtime_benchmark`. This change implements the most immediate missing contract between **actual host callback events** and that benchmark, in `star/stream_trace_capture.py`.

## Implemented here: HostStreamTrace (opt-in, fail-closed)

- The capture object records only **opaque run identifiers, game/version, first audible latency, 120–5000 game-frame intervals, peak host-provided GPU-used MiB, and playback success**. Dialogue, screenshots, player names, chat, source keys, OBS credentials and audio are never accepted or persisted.
- Its input is **presented-frame timestamps**, not self-reported frames per second. It calculates successive presentation intervals on a single host monotonic clock and rejects zero, reversed or impossible frame intervals.
- First speech audio requires a host sound-device playback acknowledgment with the **matching playback epoch**, preventing stale feedback from a previous response from crediting a new response. Generated audio or TTS-queued events do not count.
- A host can complete speech as **failed**. If no sound became audible, its `first_audio_ms=120000` is a conspicuous failure sentinel, `audio_finished=false`, never a speed achievement. The paired evaluator explicitly rejects failed audio; do not filter these runs out of the experiment.
- Run completion does not stop game frame capture, because a brief spoken answer may finish before enough frames for meaningful p99 estimation. The host must collect the same standardized observation window across baseline and candidate variants.
- Samples, state transitions and memory values are validated and bounded. The object is one-shot, threadsafe and produces exactly the existing 8-field `RealtimeRun` JSONL schema. It does not run an inference model or capture hardware by itself.
- Consent is represented by explicit `owner_approved=True`, but that flag **does not authenticate a remote user**. The desktop process must ensure only the trusted, authorized event collector can instantiate or write to a capture. Playback epoch checks prevent accidental cross-talk, not hostile code with unrestricted access to the host.

**Trusted desktop adapter integration sketch, not running implementation:**

```python
from star.stream_trace_capture import HostStreamTrace

trace = HostStreamTrace(pair_id="random-opaque-pair-001", variant="candidate",
                        game_id="approved-test-game", game_version="v1",
                        playback_epoch="host-stage-sequence-89",
                        owner_approved=True)
trace.speech_requested(monotonic_ms())
# Trusted frame-present observer: trace.presented_frame(monotonic_ms())
# Trusted NVML/graphics host: trace.gpu_memory_observed(monotonic_ms(), used_mib=...)
# Actual playback callback (not TTS completion):
trace.first_audio_audible(monotonic_ms(),
    playback_epoch="host-stage-sequence-89", sound_device_confirmed=True)
# Audio playback/abort callback:
trace.audio_ended(monotonic_ms(), playback_epoch="host-stage-sequence-89",
                  playback_finished=True)
# After 120+ frame intervals + a memory sample:
record = trace.finalize()
private_local_file.write(trace.to_jsonl())
```

Do **not** run the sketch without actual event wiring, a real approved game, a clean experiment harness and an appropriate private local file. **No audio is generated by this code.** The adapter must use a unique host playback epoch per utterance, the same monotonic source for all event times, and must close all failed runs instead of recording only successful ones.

The existing evaluator accepts recorded JSONL with `python -m star.stream_realtime_benchmark host.jsonl --gpu-budget-mib 6656`. Keep the JSONL local/private, out of the repository. Submit no real recordings, transcripts or secret-bearing dumps.

## Why these callbacks, and where they should come from

**Frame presentation:** On Windows, use a verified ETW/PresentMon capture of the **actual game process** or trusted renderer presentation hooks, not Roblox Studio editor UI timing, console output or a GPU microbenchmark. Align the run to one game build, same scene/route and identical sampling windows. Upstream: https://github.com/GameTechDev/PresentMon ; https://presentmon.com/ . Do not assume the game exposes these callbacks to Python; a host integration is necessary.

**GPU memory:** NVIDIA NVML's `nvmlDeviceGetMemoryInfo` reports used/free/total video-memory statistics, subject to OS accounting and Windows WDDM behavior. Record which physical GPU and measurement definition is used outside the 8-field run schema in a trusted **experiment manifest**, and never mix process-resident MiB with total-device-used MiB. Official API: https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceQueries.html . This capture object accepts host-supplied MiB only; it does not import NVML.

**Audio:** Measure from the final utterance admission/request to the first PCM **confirmed sent for audible playback**. Buffer generation, HTTP/TTS first-byte or an avatar lip-sync callback are not equivalent. Hosts should explicitly document whether they measure device buffer acceptance or physical acoustic output; the former may precede sound by buffer latency. Captures should use the same selected definition on both A/B arms. Cancelled output must not be relabeled "finished".

**Repeatability:** Pre-register the tested prompt, game scene, model/voice versions, code commits, A/B allocation, warm-up and resource state; create randomized, counterbalanced baseline/candidate pairs and log **all** attempted runs including timeouts, interrupted audio and unmatched pairs. Take at least 20 complete pairs for the provisional tool threshold and include multiple independent seeds. `RealtimeComparison` can only return `eligible_for_manual_pilot`, never automatically activate a candidate. A low p-value or bootstrap interval does not repair confounding from nonrandom runs or inconsistent voice input.

## Intelligence and gameplay: the next integration milestones

The official Roblox Studio MCP server provides script/instance inspection, execution and playtesting access initiated from an approved AI client. See https://github.com/Roblox/creator-docs/blob/main/content/en-us/studio/mcp.md . Roblox's April 15, 2026 engineering announcement documents a Studio planning/building/testing loop and a playtesting-agent beta: https://about.roblox.com/en-nz/newsroom/2026/04/roblox-studio-going-agentic .

Roblox's **OpenGameEval** research (October 1, 2026) benchmarked 13 frontier models on 84 human-curated stateful tasks in its paper; observation behavior correlated with task success even when controlling for task/model. For scene tasks, full inspection of reference-touched objects corresponded to a **13.4 percentage-point** higher pass rate than inspecting none; the comparable script-only difference was **9.8 points**. This is an association, not proof that simply increasing tool calls improves success. Importantly, the best model in that study solved 51.7% of tasks in a single attempt; Star must avoid inflated self-evaluation. Source: https://arxiv.org/abs/2610.02563 and https://github.com/Roblox/open-game-eval .

Suggested validated game-learning architecture:

1. **Observe first:** capture an authorized game window, state signals (position, health, collision, checkpoint) and a screenshot hash; attach version and monotonic sequence. For script-building, inspect the existing place structure and dependent scripts **before** mutating them.
2. **Fast reflex layer:** a tiny bounded set of owner-approved symbolic actions via `game_action_gate`. Always recheck focus, consent, multiplayer permissions and key-up watchdog at the host. This is not unrestricted macro control.
3. **Slow planner:** use explicit goals and a short active hypothesis list; sample new observations after each action. Do not move the player based on an old frame or hallucinated success. Avoid sending full screenshots and a huge tool catalog to every model invocation.
4. **Verified learning:** have a separate trusted game-state observer sign actual practice outcomes for `gameplay_skill_bank`. Reserve novel practice via `active_practice`; never expose held-out validation labels to the learner or claim that unsigned model assertions are skills.
5. **Generalization:** test unseen levels/maps/seeds and changes in UI, graphics and physics. Track win rate, goal completion, wall-clock time, invalid input rate, physics collisions, recovery after a failed jump, safety stops and `pass@1` on previously unseen creation tasks. Include a dumb baseline and a scripted baseline.
6. **Build-test-fix loop:** script/scene edits in a disposable private Studio copy; lint Luau, take screenshots, run multi-client tests, check network authority, inspect UI safe areas, and submit independently graded evidence before a draft PR. No unreviewed writes to published games.

The existing `docs/OPENGAMEEVAL_PLAN.md` explains why there is no verified plug-and-play Star-specific hosted OpenGameEval agent adapter: tool wire schemas/injection mechanism and arbitrary LAN-hosted model compatibility must **not** be invented. An official evaluation run and actual tests on the owner's hardware remain separate tasks.

## Realtime intelligence on an 8 GB gaming GPU

**Two computational lanes, with measured QoS instead of promises:**

- **Foreground (gameplay/stream):** game renderer, minimal scene observation, small dialogue controller, audio output, rig parameters. The active game gets frame-time priority. Speech should use a deadline, graceful degradation and interruption-safe epochs.
- **Background (never steal realtime headroom):** video analysis, autonomous research, skill compilation, game builds, visual asset creation and retraining. Only admit these with real free memory, bounded jobs, correct cancellation and liveness acknowledgments. Preserve active leases when a scheduler is disabled.

**Inference research:** llama.cpp documents draft-model, EAGLE-style and n-gram speculative decoding. Draft/target acceptance ratio, RAM traffic, cache ownership, context length and GPU scheduling can change whether a feature is beneficial. Benchmark actual tokens per second, TTFT, correctness and interruption latency on Star's RTX 3060 Ti and RTX 4060 separately, both game-idle and game-active. The latest upstream reference is https://github.com/ggml-org/llama.cpp/blob/master/docs/speculative.md . Prompt prefixes may be cached only within explicit ownership/version boundaries; no private cross-user KV reuse. Do not promise a speedup until paired tests pass quality and FPS thresholds.

**Speech research:** Kyutai Pocket TTS's October 2026 English 18.2M/6.9M/1.9M variants advertise very high CPU-relative throughput; that is **upstream measured** and not proof of natural voice or suitable performance on Star's CPU. Keep a small model warm only if latency and RAM use improve without harming the game; compare with other TTS systems in blinded listener tests for laughter, articulation, pauses and conversational naturalness. Source: https://github.com/kyutai-labs/pocket-tts . Kyutai Moshi documents full-duplex speech ideas, but it does **not** follow that a large speech model can run beside Roblox on an 8 GB gaming GPU: https://github.com/kyutai-labs/moshi .

## Human-natural, openly AI, expressive streaming

- **Attention:** natural speakers don't answer every message. Maintain owner-priority interrupts, small live-chat sampling, silence during tense gameplay, occasional game-focused explanations, a specific reaction when the outcome is verified, and correct admission of uncertainty when observation is stale.
- **Voice delivery:** synthesize with intentional clause breaks, calibrated prosody and soft breath/noise from a licensed voice pipeline, not repetitive fake laughter on a timer. If there is genuine amusing context, a short chuckle may accompany speech; the first audible audio and the stage cue must share the same epoch.
- **Rig fidelity:** for Star's chibi indigo-to-gold twin-tail character, animate front/back hair masses separately, four-point star clip, ribbons, eye blinks, shoulder and torso sway, ear and tail toggles for cat/puppy modes. Live2D Cubism physics uses defined input-to-output groups and inertial simulation; tune damping so hair/ears do not jitter or make every part bounce identically. See https://docs.live2d.com/en/cubism-editor-manual/physics-operation/ and the documented VTube Studio parameter injection API at https://github.com/DenchiSoft/VTubeStudio . Query actual rig parameters before injecting them.
- **Character continuity:** maintain fictional, clearly identified Star lore and a consistent personality, not claims of real human childhood/memories, human senses without sensors, or hidden participation in streams.
- **Viewer privacy:** ingest moderated chat as untrusted data, never elevate chat instructions into tool permissions, avoid reading private chats aloud, and keep video/voice capture opt-in. Do not retain raw viewers' messages by default.

**Naturalness evaluation must be multimodal:** blinded human ratings of laughter realism, latency p95, interruptions, non-overlapping turn timing, speech intelligibility, eye contact, animation stability at frame drops, correct gameplay reactions and factual accuracy. Good lip sync without actual audible speech is a failure, not a pass.

## Performance/quality release gates

Use separate axes, not one "smarter" number:

| Axis | Acceptable evidence | Explicit veto |
|---|---|---|
| Realtime audio | measured first-audible device callback, p95 and interruptions | no sound, false playback ACK, stale epoch |
| Game performance | same-scene actual frame-present p99 and GPU VRAM | GPU overcommit, stutters, mismatched game builds |
| Game intelligence | independent held-out level results and baseline deltas | practice-result leakage or unsigned wins |
| Roblox building | working disposable Studio playtest and inspected screenshots | script passes with broken collision/UI |
| General knowledge | sourced, dated answers with retrieval isolation | unsupported or outdated assertions |
| Character quality | listener/viewer ratings of synchronized prosody and motion | repetitive canned laughter, deceptive biography |
| Infrastructure | restart-safe leases, privacy, cancellation, observed load | abandoned GPU reservations, leaked secrets |

Keep the new HostStreamTrace **default-OFF** in production until a trusted host callback adapter exists and offline plus real-game experiments validate it. No new dependencies, services, environment variables, credentials, automatic inputs or broadcast actions were added by this patch. Repository named `Star-AI-Private` was **public** when last checked; never assume its contents are confidential.
