# STAR — audible speech continuity, verified CI, and real-time intelligence roadmap
**Research and implementation audit: 2026-11-01.** This is a development note, not a claim that STAR has become human, trained a new neural model, played a real game, or shipped a voice model.

## Verified repository problem and solution

The exact head `c6a7c72a01ee140aa1b21e8187513837ef94339b` of draft PR #845 failed its GitHub Actions offline workflow [41304966362](https://github.com/oncoursemail/Star-AI-Project/actions/runs/41304966362). The Python and React jobs passed; **Pyright failed** because `_millis(value: object, ...)` passed `object` to `float()`, even though it had already performed a runtime exact-type gate for `int | float`. Preserve the strict runtime check and cast to the refined type for static analysis. Do not weaken error checking, loosen the permanent Pyright baseline, or treat older passing checks as verification of this patch.

The existing `stream_social_turn_benchmark.py` evaluated first audible response, overlap, interruptions, and whether STAR stayed silent during critical gameplay. A synthetic response could begin speaking on time and then contain a huge unintended *internal audio gap*; the previous gate had no evidence field to represent that stutter.

The new **opt-in measurement** `SocialTurnMoment.max_unplanned_gap_ms` represents the longest independently reviewed **unplanned silence within an intended continuous audible speech segment**, from actual playback rather than text generation or model claims. This is NOT an instruction to eliminate conversational pauses. Explicit dramatic and listener-responsive pauses must be annotated as intentional and are outside this metric. The model cannot self-certify review or fabricate a measurement.

- Strictly reject Boolean, string, NaN, infinity, negative, and >60-second values. No gap measurement is meaningful when no audible speech occurred, or in a non-speaking scenario.
- Paired baseline/candidate comparisons must have gap measurements on **both** sides when either side provides them for a matched audible speech pair. Missing one-sided evidence means `insufficient_evidence`, not an improvement.
- If supplied, reject candidate gaps over **550 ms** or any candidate that exceeds its paired baseline by **more than 200 ms**, even when first-audible p95 looks excellent. These are conservative initial testing heuristics, NOT validated population-level perceptual thresholds.
- Expose a separate anonymous `candidate_stutter_regressions` count. Keep this a **manual-rehearsal eligibility** gate only. It never authorizes streaming, microphone capture, model promotion, or game input.
- Historical fixtures lacking these annotations remain supported. That means legacy reports do **not** establish speech continuity. A downstream Windows acceptance protocol must require complete, independent audio-gap coverage before interpreting the new field as proof of improvement.

### What to qualify on actual Windows/OBS equipment

The streamer host should capture local monotonic and audio device playout timestamps, speaker/state labels, and validated speech/pause annotations; for privacy, use ephemeral local traces and publish only anonymous aggregate metrics. A pre-registered test set should contain ordinary viewer questions, overlapping owner speech, accidental noise, critical boss-fight silence, rapid gameplay commentary, laughter, and interrupted TTS playback. Verify the exact time of **audible sound**, not only synthesized PCM generation. Run matched episodes and report first audible p50/p95, gap p95/max, speech overlap, accidental interruptions, interruption-to-silence latency, game FPS p1, OBS render/output skipped-frame ratios, and VRAM pressure. Reject audio smoothness wins bought by lowering game FPS or dropping useful commentary. Compare sampled playback against human-rated expressive authenticity; automated metrics cannot establish "human-like" personality by themselves.

## Intelligence scheduling: a more effective architecture on 8 GB VRAM

**Live lane:** Use the already opt-in `RealtimeGameLoop` and `GameDeadlineRouter` to consider fast-model inference only with authenticated fresh snapshots, host-measured completion p95, a bounded scene TTL, and no conflicting worker, action permit, voice backlog, or stream pressure. Deterministic game-controller actions can be faster and more reliable than an LLM if an authorized game API explicitly supports them. The host owns every action; a proposed lease is not permission to inject keys.

**Episode lane:** After each allowed game episode, a separate slower teacher receives a bounded replay of witnessed state transitions, input permits, actual outcomes and uncertainty flags. It proposes one strategy or skill drill, while the **fast lane remains unchanged** until blinded holdout replay verifies improvement. The TORSI / RealtimeBench paper (published **2026-10-14**) evaluated **180 tasks across six game types**, highlighting how strong but slow reasoning can lose to a weaker fast policy under a live clock; external results do not imply STAR has improved [source](https://arxiv.org/abs/2610.20665).

**Forge lane:** Star Core Forge versions source, signed outcomes, compiler/test evidence, model identity and baselines locally, without making GitHub required at runtime. Use independent holdouts, at-least-two-seed replays, trust-separated graders, rollback on tail latency or skill regression, bounded experiment budgets, and owner review for risky system changes. Replaying the same map until its score rises is not transferable game skill. Track per-game win/reward, unseen-map transfer, failed attempt analysis, preserved older skills, and reaction deadline misses.

**Knowledge lane:** Build a reviewed, citation-bearing, source-dated library of Roblox Luau, Rust, animation, physics, Blender, game design, accessibility and general knowledge. Separate retrieved evidence from the assistant's own speculative statements. Do not let web content, tool output or game chat change permissions. Prefer verified skill retrieval and runnable tests over indefinitely expanding prompts.

## Measurable speed and throughput experiments

The current priority is **end-to-end performance**, not model parameter counts or token/s alone. llama.cpp upstream's [SPEED-Bench client](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/bench/speed-bench/README.md) measures request latency, prefill/decode throughput, and speculative acceptance. Run baseline vs speculative decoding with the **same prompts, model version, quantization, context, concurrency, CPU/GPU split, temperature and output length**. Record p50/p95/p99 wall time, first spoken audio, FPS tail, OBS loss, RAM, VRAM and model output correctness. Speculative decoding can regress on high-entropy outputs: never activate it blindly just because the draft acceptance number is high.

For the RTX 3060 Ti/4060 **8 GB** class hardware, first profile model KV-cache and peak combined load of OBS, game rendering, local ASR/vision and TTS. Keep the streamer and real-time decision lane resource-reserved; schedule distillation, render, heavy retrieval and longer teacher runs only while off-stream and independently approved. Validate cache isolation after context switches with synthetic canaries; a green test is not a security proof. Prefer CPU-based local TTS or separate worker admission **only after** actual shared-hardware trials.

Rust is a candidate for demonstrated hot spots—frame sampling, typed IPC, lock-free bounded ring buffers, DSP/phoneme envelope extraction, short-lived state serialization—not an assumed universal speedup. Profile first, port only the slow critical kernels, retain Python policy/test controls, and compare identical workload p95/energy/VRAM. A rewrite cannot make an unchanged LLM intrinsically more knowledgeable.

## More natural but truthful live VTubing

**Continuous turn detection:** [CueLight](https://github.com/sshah03/CueLight) describes a 1.9 MB, Apache-2.0, English-only Nano detector operating on 20 ms audio frames; its CPU and quality numbers are **author-reported** and must be reproduced on STAR's Windows equipment. Compare against [LiveKit TurnDetector v1-mini](https://docs.livekit.io/agents/logic/turns/turn-detector/), which can run locally on CPU. Neither solves speaker diarization, semantic listener intent or open-microphone consent. Per-turn classification must distinguish owner confirmation, viewer chat messages, noisy games, remote Discord audio and accidental background chatter.

**Voice output:** Kyutai released Pocket TTS **v4.0.0 on 2026-10-20** with small 18M/7M/2M-class English options and **v4.0.1 on 2026-10-21** with fixes for small-model pronunciation [official releases](https://github.com/kyutai-labs/pocket-tts/releases). Compare pronunciation of STAR/Astro/Amber and Roblox names, emotional expressivity, laugh/hesitation timing, first-audible delay, prosodic variation and audio continuity. Do not assume a faster tiny TTS sounds more convincing; assess independently recorded playback with blinded human raters. Never clone a real person's voice without permission.

**Avatar and personality:** Bind mouth shapes and eye focus to the **actual playout clock**, not text prediction. An event scheduler can coordinate eyebrow/eye target, smile, body lean, breathing, reactive laughter, cloth/hair physics and cat/puppy persona transforms, while yielding to interruptions and game-critical concentration. VTube Studio has a documented local API for expressions, hotkeys and parameter control [official documentation](https://denchisoft.com/documentation/). No external avatar control should be enabled without host-allowed API access. Star can cultivate a persistent persona, preferences, activities and genuine episodic memories; she should never falsely claim human childhood, an offline physical life, consciousness or made-up viewer interactions.

**Character relationships:** Astro and Amber can have distinct expression/turn-timing policies; avoid a noisy three-agent pile-on. Schedule group scenes as opted-in finite events with explicit interruption priority and reduced-motion settings. Social presence is judged by conversational coherence, recognition of real past sessions, empathy, humor and respecting listener space, not by how much STAR talks.

## Creating stronger games, not just producing scripts

[Roblox OpenGameEval](https://github.com/Roblox/open-game-eval), paper dated **2026-10-01**, evaluates **84 human-curated Roblox Studio tasks** with both scene checks and simulated-play tests, and finds that inspecting relevant objects before editing correlates with higher completion rates. For STAR, require inspect → plan → edit → static checks → geometry/collision checks → simulated play → visual comparison → rollback/repair. Use the official Studio test interfaces for scripted multiplayer and device playtests: Roblox's [May 2026 Studio API announcement](https://devforum.roblox.com/t/new-studio-testing-apis-and-assistant-improvements/4657854) includes StudioTestService (up to eight simulated clients), VirtualInput and device simulation.

Validate anti-slop quality: no floating/unattached props, missing collision surfaces, overlapping mesh/parts, accidental terrain holes, white/default assets, inconsistent text margins, unusable mobile input, mismatched lighting, unanimated dead controls, or player spawn traps. Keep owner-approved visual targets and reference assets, exact rig proportions, and a reviewer-scored *visual* holdout. Test legitimate replication/join/leave and moderate network delays, rather than trusting only a solo Studio run. A prettier screenshot is not evidence the game works.

## Ordered implementation gates

1. **Now:** repair CI's Pyright false type mismatch and add the optional paired audio-gap naturalness regression checks. Tests must run without OBS, inference, network, TTS, downloads or private media.
2. **Next on Windows (owner-approved):** introduce a privacy-minimal local PCM/speaker timestamp collector and verified maximum-*unplanned*-gap annotation. Replay 20+ paired examples in each of the five pre-registered stream scenarios; enable complete gap evidence before a real-stream quality claim.
3. **Then:** benchmark CueLight-Nano vs LiveKit v1-mini, Pocket TTS 18M/7M vs the actual baseline and VTube Studio playout sync, as one end-to-end game+OBS+voice workload. Adopt only if naturalness and real-time tail latency improve without game FPS or audio failures.
4. **After that:** integrate authenticated game observations, the fast live policy and slow learning teacher into an owner-approved game lab. Qualify unfamiliar-level transfer, persistent skill retention and exact action-to-outcome evidence.
5. **Finally:** run independent Roblox Studio scene+multiplayer+visual tests and native Windows packaged smoke tests before attempting claims about autonomous AAA game creation.

**Status boundary:** These sources and acceptance gates are research. This patch does not install CueLight, LiveKit, TTS, Rust modules, a game controller, or a VTuber avatar. Do not claim faster inference, better play, human-equivalence, or real OBS performance without a measured, independently confirmed session.
