# Star AI: actual TTS PCM -> lips, and next intelligence milestones

**Research and implementation:** October 29, 2026. **Scope:** local-first,
opt-in, offline-verified VTuber component plus a prioritized cross-domain plan.

## Implemented now: remove synthetic animation-level guesses

Star already had a motion planner (`stream_motion.py`) and a
consumed-audio-playhead-locked renderer (`stream_playout_clock.py`). They
expected a caller to provide `AudioLevel` readings. No core implementation
decoded Star's actual TTS PCM into those readings. A text model can invent
amplitudes; that is **not** equivalent to the waveform the audience hears.

This change adds `star/stream_pcm_envelope.py` and
`StarPlayoutClock.arm_pcm16()`:

- Accept **signed 16-bit little-endian PCM** already generated by an authorized
  local TTS pipeline. Mono or stereo, 8--192 kHz, up to 15 seconds. No capture,
  external API, ffmpeg process, model request, microphone, or network access.
- Work incrementally on chunks, without retaining PCM, using standard-library
  `array('h')`. PCM16 processing works on Python 3.13+ where `audioop`
  was removed. Windows and big-endian hosts both decode little-endian bytes.
- Calculate bounded RMS energy at 10, 20 or 40 ms. **Tag measurements at
  the END of each window**, preserve real duration, and normally prepend a
  zero at t=0. At the exact 15-second/10-ms capacity limit, the redundant
  zero sentinel is omitted; the planner treats times before the first sample
  as silence. The mouth cannot move before audio evidence exists.
- Compute RMS separately across both stereo channels before combining energy;
  a phase-inverted signal must not cancel to artificial silence. Optional,
  host-chosen noise floor and fixed gain control only avatar parameters.
- Tie the result to the **existing audible-stage approval**. The renderer
  still needs an independently observed sound-device *consumed samples*
  counter and its own render-lease check. Queued PCM is not audible PCM.
- Reject empty, truncated, oversized, impossible, nonfinite or malformed
  input. All controls remain disabled until the owner-controlled stage enables
  them. Caller-supplied audio is strictly host-side and never a chat tool.

A representative host sequence is:

```python
# Executed ONLY by Star's trusted local audio host, not a model/tool.
# After owner opt-in, after a preapproved StagePlan becomes physically audible:
armed = playout.arm_pcm16(
    plan, pcm16le=generated_tts_pcm, sample_rate_hz=24000, channels=1,
)
# Render nothing until the audio backend independently measures consumption:
if armed:
    playout.observe_playhead(
        plan, position_s=actual_consumed_frames / 24000,
        sampled_at=trusted_monotonic_clock(), playing=True,
    )
    frame = playout.sample(plan)
    if frame is not None and playout.current(frame):
        host_send_authenticated_avatar_frame(frame)
```

The sequence is illustrative; `host_send_authenticated_avatar_frame` is not
a function added in this update. Existing `AudibleAvatarSession`,
`DeviceAudibleSampleHost` and `VTubeLocalHost` remain the real host bridges.

### Verification and performance limits

- 12 new deterministic PCM tests cover real byte conversion, silent-to-voiced
  transitions, opposite-phase stereo, split byte chunks, fractional sample
  rates, truncated input, audio caps, stage gating and physical-playhead lock.
- Existing motion, playout, audio-device and avatar adapter regressions are
  included in the selected suite (run result recorded on the PR).
- Linux host microbenchmark (development machine, deterministic 5 seconds of
  48 kHz stereo PCM): 960,000 source bytes, 240,000 PCM frames, 251
  RMS envelope points, median **113.07 ms CPU** over 8 sequential runs
  (110.80--120.22 ms); this is a **PCM conversion-only** measurement, not
  neural inference speed, OBS latency, GPU usage, or human-perceived quality.
- Final audio will still need approved Windows test recordings, real TTS
  output, microphone-free output-loopback verification, real OBS capture,
  and comparison against existing output QoE checks before a live claim.
- Amplitude-only mouth opening is **not phoneme-perfect**. A true viseme
  track needs properly timed phoneme/viseme alignment and a rig mapping; do
  not hallucinate phonemes from subtitles or generated text.

## What actually makes Star faster and more intelligent

### 1. Protect the realtime gaming loop before background cognition

Have one high-priority budget for game FPS, sound-output and avatar rendering;
a separately capped budget for conversational TTS and chat; and a lower
priority queue for visual perception, large reasoning and research. Star's
existing `StreamBrainGovernor`, `AdaptiveQoS` and audio playout watchdog
already provide the basic safety/control structure. Next integrate real
Windows host telemetry and measure **time to first audible syllable, FPS
1%-lows, interruption delay, and mouth/sound offset**. Do not claim speed
from a faster token counter alone. Keep model-serving endpoints local by
default; avoid enabling arbitrary server tools.

llama.cpp's server documents continuous batching, prompt caching, and
speculative decoding. Compare configurations with unchanged tasks, stable
prompt prefixes, time-to-first-token, end-to-end task completion, VRAM and
FPS headroom. Cache model-specific public reference prefixes; do not cache
viewer messages, secrets or private streaming memory in shared slots.

### 2. Learn to play through actual verified interaction

Use **private/authorized** Roblox Studio play sessions, host-owned action
bindings, fresh game observations, finite action budgets and externally
checked objectives. Require exact action->observation->outcome traces.
Choose practice tasks that increase difficulty after repeated verified
success, but keep held-out levels and win criteria inaccessible to Star.
Real progress means she can succeed on previously unseen layouts without
a human feeding her the solution. GameWorld and OpenGameEval provide
evaluation patterns; neither constitutes evidence that Star has mastered
Roblox or arbitrary games.

Roblox Studio's documented `StudioTestService`, `VirtualInput`, and
`StudioDeviceSimulatorService` allow reproducible playtests, multiplayer
and UI/device regression. They do not authorize live third-party game
automation, public server actions, or circumventing game rules.

### 3. Make game creation visually correct, not merely compilable

Start with real spatial snapshots and full dependency inspection. Require
collision/anchoring and placement rules, playability (spawns, objectives),
screen captures for UI/VFX, animation preview, and **after-change
regression** against a prior saved baseline. Multi-agent builders should
independently test changes, record provenance, and present only passing
candidates for owner review. Preserve editable 3D/Luau source, not just
generated concept art.

### 4. Improve general knowledge and long-term interests

Maintain three separate scopes: source-verified reference facts with date and
revision; learned **experiences** tied to independently observed events; and
hypotheses/ideas clearly labeled speculative. Retrieve at question time.
Flag expired sources, contradictions and missing evidence. Keep large documents
outside model hot context and stable public facts in cache-friendly prefixes.
Measure accuracy on fresh, hidden multi-domain questions, not recalled
practice answers.

For a believable streamer personality, prefer continuous experience-based
projects: games she tried, strategies that failed, code she revised, friends
who actually opted into conversation, and real milestones. She can express
playful curiosity, excitement, frustration-as-performance and humor without
claiming a human life, consciousness or memories she does not have.

### 5. Natural conversational flow with actual output verification

LiveKit documents combined acoustic/semantic end-of-turn detection, optional
lightweight CPU `v1-mini`, and adaptive interruption handling. These methods
are candidates for local evaluation, **not** dependencies installed by this
change. Star needs to distinguish short backchannels from actual
interruptions, choose silence during tense moments, handle overlapping chat
fairly, and cancel old TTS before generating new audible sound. Eye focus,
blink, bows, hair and body physics should follow the active verified event and
the physical output playout clock. VTube Studio documents authenticated
parameter injection; do not expose the websocket or plugin token to chat.
