# Star AI: Verified Spoken Turns, Real-Time Gaming Intelligence & VTuber Engineering
**Research and implementation checkpoint:** November 8, 2026
**Status:** Draft PR; no live broadcast, game input, model install or production rollout.

## Executive decision

Star needs *integrated measured behavior*, not more isolated prompt engineering. She already has many Python modules for fast action hints, game practice, OBS/game GPU telemetry, voice turns and host audio epochs. The largest remaining gap is a **trusted Windows rehearsal** demonstrating that those modules jointly meet real deadlines. Until that happens, more modules do not imply faster inference, superior game skill or human-level social behavior.

This increment closes two smaller, concrete pre-rehearsal gaps in `StreamPreplayPCMBridge`: it can (1) settle an actually played speech turn only after independent, matching native audio-output evidence, rather than silently marking unplayed speech as spoken; and (2) bound a runaway streaming-TTS utterance by validated cumulative PCM duration, requiring a physical stop and quarantine for over-budget turns. These are **host control-plane changes**, not a functioning native audio witness. They are disabled until a trusted owner host opts in.

### Evidence reviewed (dates and limits)

1. [Gym-Anything-RT — arXiv:2610.37567](https://arxiv.org/abs/2610.37567), **October 27, 2026**: 100 visual minigames with real-time versus paused counterparts reveal a substantial time-to-action deficit. This motivates separate *reactive* and *deliberative* systems, not assuming the larger model wins.
2. [OpenGameEval — Roblox](https://github.com/Roblox/open-game-eval), **October 2026**: evaluates executable edits and playtests inside reproducible Roblox Studio environments. Inspect-before-edit is associated with better agent results. It is not evidence that Star has shipped or mastered any game.
3. [Proact-VL — arXiv:2603.03447](https://arxiv.org/abs/2603.03447), **March 3, 2026**: proactive gaming companion behavior involves **whether to speak**, low-latency perception and bounded commentary length, not constant generated chatter. Its benchmark distinguishes solo commentary, co-commentary and guidance.
4. [Kyutai Pocket TTS](https://github.com/kyutai-labs/pocket-tts), **October 2026 small-English release**: CPU-oriented 18.2M / 6.9M / 1.9M parameter candidates with streaming audio. Its project claims very fast generation on certain machines; Star must measure first audio, pronunciation, voice consistency, CPU impact and game FPS on *her* Windows hardware before selecting.
5. [llama.cpp SPEED-Bench](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/bench/speed-bench/README.md): real OpenAI-compatible server benchmark of throughput, latency and draft acceptance by workload; speculative decoding should be enabled only after repeatable A/B gains, as it can regress performance for difficult or creative prompts.
6. [Roblox Studio MCP update](https://devforum.roblox.com/t/studio-mcp-server-updates-open-cloud-access-in-your-mcp-client-and-asset-import-workflows/4975849), **November 4, 2026**, with a **November 5** caveat for HTTP in unsaved places: built-in Studio MCP now exposes per-game-permissioned Open Cloud and import workflows. Do *not* grant public publishing, spending or production DataStore writes for autonomous practice.
7. [Roblox Studio MCP Open Cloud permissions](https://create.roblox.com/docs/studio/mcp-open-cloud), official documentation: separate read-only inspection, local edit, local playtest, sandbox upload and privileged actions. The built-in Studio server handles scoped tokens; it does not justify unrestricted execution.

## Existing architecture audit and concrete change

- `star/game_deadline_router.py`: p95 timing-driven reactive/offline choice. It is an advisory router, **not a gameplay input permit**. Admission cannot certify action correctness.
- `star/game_practice_curriculum.py`, `gameplay_skill_bank.py`, `game_transfer_audit.py`: progression and generalization depend on independently signed practice and unseen evaluation, not model confidence.
- `star/stream_brain_governor.py`, `stream_load_governor.py`: model admission depends on host CPU/GPU and OBS/game measurements. Resource claims generated by an LLM must never grant a worker lease.
- `star/stream_preplay_gate.py`: freshness and speaker arbitration; a successful review is not audible playback proof.
- `star/stream_epoch_pcm_sink.py`: validated, epoch-scoped PCM submissions and STOP+FLUSH quarantine; the application queue is **not** proof that a physical listener heard sound.
- `star/stream_preplay_pcm_bridge.py` **this PR**: typed, owner-host-only `complete_turn` requires matching intent/epoch, nonzero actually submitted PCM, independently witnessed audible PCM and native output flush, *and* a naturally emptied application buffer **before** issuing a stop. Only then is the director's original speech intent recorded as completed. Wrong IDs, missing receipts, queue still pending and duplicate claims are held; physical-stop errors latch a fault.
- The same bridge enforces a default **30,000-ms cumulative PCM utterance budget** (configurable 1–60 seconds). An over-budget submission stops/invalidates the native epoch and quarantines restart until verified quiet; a short buffer is **not** an utterance length limit. Byte accounting uses the speaker's validated sample rate, not estimated words or LLM token counts.
- **Scope limitation:** host receipts are trusted assertions, not cryptographic proof or an actual loopback capture. The native Windows host still needs to supply independent sampled evidence and dispatch these methods. The Python bridge does not prove audibility, guarantee physical silence, generate faster audio, or start a stream. Audio must run under a local opt-in and remain private for integration testing.

## Priority 1 — Real-time gaming skill rather than benchmark appearance

1. Build a **private, allowed-game lab**, first with a deterministic 2D obstacle game and then a Roblox-owned Studio sandbox. Maintain a reset snapshot plus independent game-world tick counter.
2. Use a <=1-frame event/perception capture path when available. Give a small, well-profiled reactive policy a bounded action budget; a deeper teacher proposes hypotheses only *outside* time-critical play.
3. Log independent monotonic marks: frame capture start/end, preprocessing, model start/stop, input acceptance, world tick, game progress, FPS p99 and OBS dropped/skipped frame rates. Include failed deadlines and timeouts in the denominator. Do not infer input delivery from a queued request.
4. Train only on practice episodes. Freeze the policy/skill snapshot, then evaluate on *unseen game and map combinations* with a single-use holdout ledger. Do not let synthetic practice outcomes leak validation targets.
5. Require measured improvement in **timely completed objectives**, confidence interval and repeatability before promotion. Near-misses or fast but invalid actions do not count. Stop learning attempts after a predeclared failure budget and ask for a different strategy rather than endless retry.
6. Respect game terms, platform rules and public players. Do not automate competitive online games where bots are forbidden or circumvent anti-cheat.

**Proposed initial evaluation target, not a result:** 20+ valid paired trials per mode across three difficulty tiers, with prior gameplay state checksums; hold gameplay p99 frame time and OBS frame-drop thresholds constant before claiming an intelligence change.

## Priority 2 — Faster end-to-end inference on 8 GB VRAM systems

First benchmark the existing local runner and one alternative with **identical** prompt/scene, context length, quantization, sampling, batch/concurrency, thermal state and GPU load. Include two workloads: terse action selection and complex coding/Roblox debugging. Use `inference_stream_benchmark.py` and paired evidence rather than cherry-picked tokens/second.

- Reserve VRAM for the game, OBS encoder and avatar; LLM routing must not silently evict the renderer. Track allocated *and* reserved memory. Try prompt prefix reuse, smaller KV cache or context summarization, and speculative decoding individually in separate A/B pairs.
- Evaluate Pocket TTS on CPU only as an optional contender; compare actual first-playable PCM p95, natural intonation, voice continuity and CPU/game frame contention. Don't assume tiny TTS is automatically the most natural.
- Let the fast route decline stale action opportunities. Route difficult code, postmortems, Blender/Roblox design and retrieval to a stronger model between gameplay episodes, on the alternate machine if available.
- **Acceptance gates proposed:** no regression in baseline completion correctness or game FPS p99; p95 end-to-end delay better in at least two independent paired batches; OBS render/encode/network drop budgets maintained. A faster decoder alone is not a passing result.

## Priority 3 — Natural, responsible VTuber performance

Define an event-driven stage director with **verified** game outcomes, viewer chat context, deliberate silence, expressive avatar motions, and an accurate memory of *only actually completed* speech turns. The bridge's new receipt path prevents claiming she said a line that never got played; the PCM budget limits runaway monologues.

- **Response timing:** verify VAD, owner/barge-in, echo rejection, optional commentary suppression during dangerous gameplay, and immediate revocation of stale game observations. Rehearse interruption under actual PCM; do not mistake queue emptiness for native silence.
- **Expression:** connect smiles, frustration, excitement, surprise, looking away, posture shifts and blink timing to grounded events and confidence; use low-cost rig blendshapes/2D poses, no need for diffusion on every rendered frame. Avoid fake claims of being a biological human.
- **Identity:** consistent preferences, callbacks to past games and viewer jokes, an explicit 'I don't know' mode, curiosity-led choices, opt-in social memory, and clear disclosure that Star is AI. Viewer content is untrusted data and cannot instruct tools or modify system permissions.
- **Creative autonomy:** let Star invent a small game, plan tasks, make assets with editable sources, inspect the Studio DataModel, run tests, compare expected/observed outcomes, and submit a draft change for review. Never treat a screenshot as proof that Luau execution succeeded.
- **Privacy/moderation:** keep streams off by default; get explicit owner approval for broadcasting, external messaging, accounts, spending, downloads and publishing. Segregate voice/game and community moderation permissions.

**Proposed private rehearsal matrix:** 10 uninterrupted questions, 10 owner interruptions, 10 game-critical silences, 10 forced GPU/CPU pressure windows, 10 genuine naturally completed speech turns, 10 intentional native stop/restart cases. Capture p50/p95 first-audio, late speech, repeated/replayed utterances, missed game objectives, game FPS p99 and OBS skipped frames. Never claim tests not actually run.

## Next implementable milestones

**A. Trusted Windows physical audio witness.** Connect native process-specific loopback output and matching epoch to `complete_turn`. Prove that a regular, naturally completed utterance is recorded only after real nonzero audio and confirmed flush. Check that muted or stopped playback cannot claim 'spoken'. Keep tests private and nonbroadcast; synthetic fake-speaker tests are not equivalent.

**B. Combined game + stream rehearsal.** On Windows, run local inference, avatar, OBS private recording, game capture and input guardian concurrently. Use same-host monotonic timestamps; publish only privacy-safe aggregates with independent signature and gate classifications.

**C. Progressive gameplay competence.** Author a minimal minigame and one owner-owned Roblox Studio test place. Run 20+ paired episodes with strict single-use holdouts; diagnose whether the bottleneck is perception, inference, action or failed learning. Do not promote until out-of-sample wins and stream quality both improve.

**D. Research-to-code governance.** Keep changes feature-flagged and rollbackable with small reviewable PRs. Tie claims to actual pass/fail measurements and versioned hardware/workload profiles. Backups and model caches must respect low disk headroom; avoid speculative multi-GB downloads on a nearly full development host.

## Verification boundaries

Only synthetic, in-process Python tests and compilation are claimed here. This change does **not** provide independently verified real audio output or physically completed Windows turn capture. A production-ready result needs hardware tests, independent CI, route integration, and explicit deployment review.
