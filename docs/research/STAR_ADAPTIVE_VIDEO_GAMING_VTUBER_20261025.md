# STAR: Adaptive Video Cognition, Real Gameplay Learning, and Natural VTuber Streaming
**Engineering research — 25 October 2026**

## Scope and status

This change adds a **real, owner-opt-in keyframe screening path** for *local video-file* understanding in STAR's existing `star.chat_media.prepare_turn -> star.video_understanding.prepare` pipeline. It is **not** a live game player, realtime webcam observer, full-duplex voice model, nor an improvement to Star's LLM weights.

Implemented: `star/video_sampling.py` scores up to three 160-pixel preview frames in each of at most six time windows; `star/video_understanding.py` decodes chosen final images at the existing 768-pixel cap and labels what the model actually saw; `star/chat_media.py` only enables adaptive sampling when the host sets `STAR_VIDEO_FRAME_SAMPLING=adaptive`. Uniform is the unchanged default. Exact repeated visual content may use fewer vision tokens. Cancellations are honored during frame extraction, and old decoded frames are never mistaken for the current video after FFmpeg failure. No network, storage of conversations, model installation or GPU operation is performed by this feature.

This conservative implementation is an **engineering heuristic**, not a reproduction of academic AKS, AdaQ, Q-Frame, or AdaFrame. Its three previews per window are an intentionally small candidate budget for consumer hardware. It prioritizes coverage of time windows, representativeness within each window, quality (avoiding black transition frames), and distinctiveness from the previous selected frame. Very nearly identical frames are removed. There is no query embedding or semantic event detector; a millisecond event missed by the thumbnails is still missed. Motion, UI and gameplay relevance cannot be inferred reliably from RGB distances alone.

## Why it matters to STAR

STAR's existing video system samples 1–6 equally-spaced images and the first 10 minutes of audio in 30-second ASR segments. Many long gameplay recordings contain repeated menus, static HUDs and loading screens. Feeding repeated stills to a CPU/GPU VLM spends processing capacity without necessarily adding evidence. The new path can select frames with greater visual coverage and pass fewer redundant images, while maintaining the honesty rule: the model has not seen anything between the reported timestamps.

Academic motivation, not an asserted STAR performance result:

- [CVPR 2025 — Adaptive Keyframe Sampling](https://mlanthology.org/cvpr/2025/tang2025cvpr-adaptive/): frame relevance and temporal coverage matter with fixed input budgets.
- [VideoBrain (February 2026)](https://arxiv.org/abs/2602.04094): learned acquisition can outperform single-pass uniform sampling on studied datasets; much more substantial machinery than our heuristic.
- [Q-Frame (June 2025)](https://arxiv.org/abs/2506.22139): query-conditioned frame selection is a promising later step, provided STAR can verify source provenance and resource cost.
- [AdaFrame (13 October 2026)](https://arxiv.org/abs/2610.19127): investigates hierarchical deduplication and information budgeting in advertising videos. Its reported savings **must not** be transplanted as benchmark claims for STAR or gaming.
- [Microsoft Video Indexer documentation](https://learn.microsoft.com/en-us/azure/azure-video-indexer/scene-shot-keyframe-detection-insight): scene detection has failure cases in continuous shots and low-quality footage. Gaming videos often have exactly those properties.

## How to evaluate/activate this experimental feature

Opt in on the trusted local STAR process, never inside a chat prompt:

```bash
STAR_VIDEO_FRAME_SAMPLING=adaptive python main.py
```

To return to the previous implementation, unset the environment variable. Model-generated text cannot enable the switch. Output remains restricted to the existing selected local video-understanding model (as enforced by `media_places.require_video_provider`). The existing maximum four images per chat turn is unchanged. Inspect `Evidence.frame_sampling`, `Evidence.times` and `Evidence.timings['frames_seconds']`.

**Acceptance experiment (before enabling by default):** Choose 20–50 lawfully usable, consented recordings with distinct categories: stationary HUD, high-motion FPS, Roblox tycoon, parkour, horror, fail-then-win, and a quiet conversation video. Make a human-labeled answer key with time-stamped ground truth **not generated by STAR**. Ask the same factual questions under uniform vs adaptive, randomize order and blind the grader. Measure (1) grounded answer correctness; (2) critical event recall and false positive rate; (3) preview+full frame extraction wall time; (4) VLM first answer latency and total tokens; (5) GPU peak VRAM, CPU/RAM; (6) whether visible HUD text is preserved; (7) cancellation and failure behavior. A single successful toy test cannot establish superiority. Gate roll-out if critical-event recall or grounding worsens, even when average latency is lower.

Expected trade-off: adaptive sampling decodes up to three cheap thumbnails **plus** final frames per time window, so FFmpeg CPU/disk work goes *up*, potentially materially. VLM image ingestion goes *down only when near-duplicate frames are pruned*. It is plausible on some clips that total time is worse. Benchmark, do not guess.

## Architecture roadmap: STAR from video understanding to game-playing intelligence

### 1. Instrumented observation, then authorized action

For STAR-owned game test environments, combine four streams with timestamps and provenance:
1. authorized game or Studio telemetry (player pose, health, objectives, collisions, object hierarchy and script errors);
2. actual screenshots/video frames, sampled adaptively within a bounded budget;
3. game audio cues and transcript, separating real audio events from ASR guesses;
4. action receipts stating which controller command was sent and whether it executed.

Run `Observe -> Estimate State -> Select Goal -> Plan -> Act -> Re-observe -> Score`. A chosen action alone is not a verified outcome. Use monotonic timestamps, action IDs, observation freshness checks, per-game consent, fail-safe stop, and no live player data collection. Roblox Studio's **built-in MCP** is the supported Studio integration; connect only to owner-approved blank/test places, restrict write capability, and validate with actual Studio playtests. Roblox's March 5 and April 15, 2026 announcements describe built-in MCP and automated testing; they do not establish that STAR has mastered them.

References: [Roblox Studio MCP documentation](https://github.com/Roblox/creator-docs/blob/main/content/en-us/studio/mcp.md), [March 2026 Studio update](https://devforum.roblox.com/t/assistant-updates-studio-built-in-mcp-server-and-playtest-automation/4474643), [April 2026 Roblox product announcement](https://about.roblox.com/en-nz/newsroom/2026/04/roblox-studio-going-agentic).

### 2. Lifelong gameplay learning rather than repetitive scripted agents

Store replay trajectories keyed by (game version, level, task, equipment, observation, selected action, independent observed result). Split by *game and level*, not just random rows. Promotion to a reusable skill requires held-out tasks and a minimum evidence count, and failures must remain in the journal. Add targeted curiosity: STAR proposes one small experiment to resolve the uncertainty that most affects the next action. A world model can predict what might happen, but its predictions are hypotheses and must be compared with observed actions. Keep simulated self-play distinct from real game performance.

References: [Google DeepMind SIMA 2 (November 2025)](https://deepmind.google/blog/sima-2-an-agent-that-plays-reasons-and-learns-with-you-in-virtual-3d-worlds/), [Voyager project](https://voyager.minedojo.org/), [DreamerV3 paper](https://arxiv.org/abs/2301.04104). None of these systems transfers its weights or abilities into STAR simply by linking to it.

### 3. Robust Roblox creation

Attach geometry assertions to generated builds: support/wall connectivity, anti-overlap collisions, grounded props, texture UV consistency, instance ownership, spawn/safe paths, UI safe areas, z-order and reference-style conformance. Supplement symbolic validators with side-by-side reference screenshots and blind human aesthetic review; 100% visual perfection is not mechanically provable. Test at multiple resolutions, avatars, Roblox streaming radii, and gamepad/mobile input, *in Studio*. Treat pass/fail as an independent observation. Preserve editable native Roblox UI and meshes.

### 4. Natural VTuber conversation, not fabricated humanity

An engaging AI avatar needs **coherent, responsive behavior**, not false claims of being a biological human or conscious:
- continuous listener with voice-activity detection and playback interruption; distinguish the streamer's speech from game audio and TTS feedback;
- high-priority game cue routing, active gameplay quiet periods, and owner/chat interruption budgets;
- speech generator capable of prosody, turn-taking, hesitations, laughter, expressive emphasis and mid-sentence reactions, with a cooldown on repeating favorite jokes;
- synchronized lip shapes, facial expression and head/eye gesture with gentle hair/ear/tail physical follow-through; user can reduce motion;
- event-sourced session context: `failed_jump`, `boss_phase`, `won_round`, `viewer_question`, each with source/timestamp/evidence; don't invent off-stream personal history;
- reviewable creator personality guidelines: cute, witty, playful cat/puppy modes, but clear AI identity.

Relevant research: [NVIDIA PersonaPlex](https://github.com/NVIDIA/PersonaPlex) (full-duplex speech, separate model license and hardware evaluation needed), [NVIDIA DyaPlex June 2026](https://research.nvidia.com/labs/amri/projects/DyaPlex/) (synchronized speech and motion research, **not integrated into STAR**), [Live2D lip-sync SDK](https://docs.live2d.com/en/cubism-sdk-manual/lipsync/) (avatar parameters require a real rig). An 8 GiB GPU is a tight simultaneous game+TTS+VLM budget; benchmark a cascaded lightweight ASR/LLM/TTS system versus full-duplex speech on the owner's actual hardware before choosing. Do not infer inference latency or VRAM from marketing demonstrations.

### 5. Measured speed and reliable two-machine infrastructure

Give the foreground game/OBS process a resource priority; any research, vision batching or training should be shed before dropping live frames. Track p50/p95 time-to-first-audio, ASR latency, game tick/frame budget, dropped OBS frames, interrupted speech residue, GPU VRAM headroom, inference throughput, and power/thermal conditions. Use bounded queues, stale-event rejection, timestamps, watchdogs, and switchable partial service availability. If Brain 1 fails, streaming must not block or restart the host game, and Star must not silently switch to a paid cloud provider.

Keep speculative decoding and caching experiments **default off until A/B testing**. [Official ggml-org llama.cpp speculation docs](https://github.com/ggml-org/llama.cpp/blob/master/docs/speculative.md) describe n-gram speculation; draft acceptance and actual speedup vary by workload and engine build. Measure identical prompts, output correctness, real game FPS and latency, not just total tokens/s. Use the existing STAR inference benchmark and experimental A/B tools where available; don't duplicate or silently enable engines.

### 6. General knowledge: licensed, verified, evaluated

Instead of arbitrarily scraping the Internet into weights, provide a revisioned evidence bank: source URL, author/license, capture date, expiry, conflict detection and citations. Public web evidence and downloaded code are untrusted; neither can grant extra permissions nor train private data without consent. Ask independent evaluators unfamiliar with the source for a held-out benchmark on language understanding, causal reasoning, code, mathematical accuracy, tool recovery and visual quality. Promote skills/knowledge only after measurable improvements and no regression on evaluation fixtures. Use retrieval selectively and respect STAR's existing default-off knowledge rules.

## Next integration checkpoints

**Near term:** compare adaptive vs uniform on authentic owner-provided video clips, add gameplay-specific frame regions (HUD, minimap, center action), track decoder latency on Windows, and run the full offline suite.

**After the explicitly authorized VTuber hardware go-ahead:** connect a read-only frame/telemetry receiver to a deterministic event director and a synthetic speech/animation sink first. Then add trusted speaker audio input, avatar rig, OBS read-only status, and finally locally authorized gameplay controls with a physical emergency stop. Keep sending/recording/streaming control separate and opt-in.

**Never claim without demonstration:** self-awareness, full human identity, unbeatable gameplay, perfect builds, learned LLM weights, realtime speech-to-avatar performance, or a demonstrated speedup. Publish reproducible measurements and failures alongside successes.
