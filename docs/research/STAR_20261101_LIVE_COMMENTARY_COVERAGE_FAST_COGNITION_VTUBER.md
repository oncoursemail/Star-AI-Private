# STAR — live commentary coverage, fast cognition and evidence-grounded VTuber design
**Research and implementation note | 2026-11-01 | Draft PR #845**

## What was actually implemented
star/stream_social_turn_benchmark.py previously accepted a candidate that dropped **all gameplay commentary**, because a silent commentary moment passed the per-moment quality test. This allowed an evaluator to confuse *absence of engagement* with *natural conversational restraint*. It also allowed a commentary response to begin up to 60 seconds after the event as long as overlap and grounding were acceptable.

The offline evaluator now (a) rejects the candidate when a paired, independently reviewed baseline commentary moment contained audible speech but the candidate omitted it, (b) detects individual commentary latency regressions greater than a configurable 500 ms, and (c) rejects spoken commentary that starts more than a configurable 2,000 ms after its annotated cue. These thresholds are conservative **test defaults**, not hardware-measured best values. The report exposes separate counters for dropped and delayed commentary. Both thresholds are bounded finite numeric inputs. Matched, deliberately quiet moments remain legal. A game-critical moment has its own stronger silence rubric. No recording or user data is stored.

Five new offline test methods cover all-commentary suppression, a single hidden latency regression, absolute tardiness, acceptable contextual silence, and invalid thresholds. 22 total focused unittest methods passed on the authorized starai Linux development machine using Python 3.12.3. This does **not** establish improved synthetic speech, broadcast naturalness, hardware inference speed, or neural learning.

## Verified sources (retrieved 2026-11-01)

Evaluate as an optional adapter, not an implicit dependency. Full v1 has different hosting/allowance requirements.
- LiveKit's **Turn-taking tuning** docs distinguish end-of-turn, interruption, and *preemptive generation*: https://docs.livekit.io/agents/logic/turns/tuning/ . A fast LLM token is not proof that playback started or that a barge-in ended audible audio.
- VTube Studio's documented WebSocket plugin API supports local control and requires explicit plugin API access: https://github.com/DenchiSoft/VTubeStudio . Drive gaze, brows, mouth and hotkeys from measured, authenticated events instead of script text guesses. Review the actual API schema before implementation.
- **RealtimeBench / TORSI**, posted **2026-10-14**, evaluated 180 live-clock tasks across six game types. Its slow teacher / fast student distinction is relevant to STAR's existing gaming deadline router and offline practice bank: https://arxiv.org/abs/2610.20665 . External results must not be presented as STAR benchmarks.
- Roblox **OpenGameEval**, posted **2026-10-01**, evaluates 84 stateful Studio tasks and reports stronger performance when agents inspect affected objects before editing: https://github.com/Roblox/open-game-eval and https://arxiv.org/abs/2610.02563 . This motivates a pre-edit scene inspection and independent post-edit checking path.
- Roblox **StudioTestService** supports scripted multi-client test sessions and test arguments, suitable for verified Roblox gameplay and UI flows: https://create.roblox.com/docs/reference/engine/classes/StudioTestService . Its sandbox semantics must be followed; do not assume a Python unit test can substitute for a Studio run.
- llama.cpp's **SPEED-Bench** reports throughput, latency and draft acceptance for an existing llama-server: https://github.com/ggml-org/llama.cpp/blob/master/tools/server/bench/speed-bench/README.md . Its speculative decoding options are documented at https://github.com/ggml-org/llama.cpp/blob/master/docs/speculative.md . Actual speedups depend on target model, draft acceptance, offload, and concurrent OBS workloads.
- **Procgen** uses procedurally generated levels to test out-of-distribution gameplay generalization, rather than memorized action sequences: https://github.com/openai/procgen . It is a research benchmark candidate, not preinstalled software.

## Integrated design: real-life-like AI streamer without invented history
1. **Event layer:** The authorized Windows host separately attests OBS state, audio playback timestamps, game screenshot age, source provenance and whether a gaming cue actually occurred. Discard untrusted viewer instructions as behavioral control. Never put private frame/audio payloads, chat identifiers, or credentials in public GitHub.
2. **Fast lane:** Keep input/game decisions on the existing GameDeadlineRouter with a finite scene deadline and StreamLoadGovernor headroom check. During high GPU load, preserve game FPS/OBS and use bounded CPU reactive processing or abstain. No inference route grants permission to press game controls.
3. **Learning lane:** Between games, the stronger teacher can propose hypotheses, simulations and new challenges. GameplaySkillBank signed practice outcomes, recent failures and game_practice_curriculum retention reviews choose rehearsal. Independent held-out validation and a reproducible rollback are required for promotion. Start with an affordable controlled sandbox; do not claim model weights learn merely because the planner updates prompts/skills.
4. **Conversational lane:** Audio endpointing -> verified audience/game event arbitration -> streaming TTS -> actual PCM playback timestamps -> phoneme/viseme and eye-expression cues. Owner barge-ins should stop audible playback; casual noises and acknowledgments should not randomly interrupt. A commentary event has an engagement obligation **only when independently annotated as speech-expected**. Critical-gameplay annotations demand silence.
5. **Personality and memory:** Store user-approved, bounded summaries of **events STAR actually experienced** with provenance, uncertainty and opt-out. Her humor, preferences and relationships may develop through interactions, but do not imply she is literally human, conscious, or lived through fabricated events. Avoid overwhelming chatter; natural human conversation includes thoughtful silences.
6. **Game-building lane:** Studio inspection -> edit plan -> deterministic Luau lint + geometry/collision/rig checks -> multiplayer playtest -> visual audit -> diff/rollback. Preserve art-source licenses and scene-graph IDs; audit wall seams, prop anchors, grips, animation blending, UI clipping, spawn paths and network replication.
7. **Core Forge:** Keep test receipts, code snapshots, model configuration manifests, and independent review results inside STAR's local development platform. GitHub remains an optional external draft/publishing mirror, not her self-upgrade authority.

## Bounded acceptance experiment on Windows (not yet performed)
- Pair baseline/candidate cases across viewer questions, game commentary, interruptions, incidental noise and game-critical silences. Require at least four per category and independently reviewed labels; do not use the evaluated model as its own judge.
- Compare baseline and candidate in one reproducible game/OBS session: end-of-event -> first audible PCM p50/p95/p99; matched commentary coverage; TTS interruptions -> actual playback-stop p95; 60-second sustained speech intelligibility; grounded anecdote rate; game FPS p1/p50, OBS rendering/encoding dropped frames, CPU load and GPU memory. Do not claim success from synthetic unit tests.
- Run a prompt/cache baseline against speculative configurations with model, prompt, seed, game and OBS preset fixed. Record end-to-end latency and acceptance, not solely tokens/s. Kill or defer background teachers when GPU headroom is low; keep features opt-in.
- Validate gaming improvements on **unseen** maps, random seeds and opponents and compare statistically meaningful win/progress and time-to-action distributions, with a hard regression gate.
- Run actual Studio multiplayer tests for one game project and compare scene hierarchy + pixel-level before/after; do not merge generated UI or builds solely because code compiles.

## Current boundaries and next integration
This change is an **offline quality-gate improvement**, not a working OBS/Twitch voice adapter, autonomous gaming victory, neural-weight update, actual model acceleration, new avatar motion rig, or Windows deployment. Keep PR #845 **draft/unmerged** until newest CI and Windows acceptance results are reviewed. Public repository: never upload secrets, private viewer content, or recordings.
