# Star AI — event-grounded commentary, real-time intelligence, gaming and VTuber architecture

**Research and implementation check:** 2026-11-04.
**Status:** implemented: exact source-event fingerprint on the StreamDirector → StarStage → bounded speculative-commentary boundary, plus local time-rollback refusal and tests. **Not implemented in this change:** actual live TTS/OBS/game control, continuous microphone barge-in, automatic game-playing policy training, broader LLM model training, or a measured increase in live intelligence or inference speed.

## Specific failure closed in this iteration

The preceding commentary prefetch path matched a prepared turn to a reserved event by `signal_id`, `kind`, `evidence` and `game_scope`, but omitted the *specific content, speaker, and event timestamp*. An event could be speculatively drafted without actually being accepted by the stage, and a later event could happen to reuse the same ID and metadata while changing the meaning. A second problem: callbacks carrying earlier timestamps than the reservation or completed draft could extend an old draft's perceived freshness.

The new `signal_origin_sha256` binds the seven canonical fields of an actual `StreamSignal`: **signal ID, kind, timestamp, detail, speaker ID, evidence, and game scope**, with a domain-separated versioned SHA-256. `StreamDirector.propose()` records the accepted event fingerprint in its issued `SpeechIntent`; `StarStage.prepare()` copies it into the real one-shot `StagePlan`. `StreamParallelCommentaryPrefetch.reserve()` fingerprints the reserved source independently and `take_for_plan()` requires a constant-time equality match to the *stage-issued* event. Hashes are not MACs or proof of external authenticity; the trusted host must still moderate viewers and attest game events. Only the source identity is compared; host-generated knowledge/context may still change independently and must be checked for relevance before speech. No chat text, speaker ID, raw hashes or voice is returned in metrics.

Each pending draft now also remembers the most recent checked host time. A `complete()` or `take_for_plan()` callback reporting time earlier than that reservation/completion invalidates the draft. This protects against stale delivery when callbacks use a broken or mixed clock domain. The host should use a single monotonic clock; an implementation cannot safely infer real time from arbitrary external callbacks.

**Impact:** a concrete correctness/speech-grounding improvement in a text-only library. **Non-claim:** it does not make model tokens appear faster; prevent hostile code in the trusted process; connect OBS/TTS; prove the host really witnessed a game event; or establish that a listener heard audio.

## 2026 research with engineering implications

**1. Speaking less can make a companion more humanlike.** Microsoft Research's **Proact-VL** (ICML 2026, published May 2026) addresses when to speak, length of content and video understanding in real-time gaming companion/guide scenarios. Implement a decision policy that deliberately chooses silence during combat, chat backchannels when appropriate, short gameplay-linked observations, and explicit owner-interrupt priority, not continuous chatter. Use independent observations and a separate quality judge; avoid fabricating victories or memories. Source: https://www.microsoft.com/en-us/research/publication/proact-vl-a-proactive-videollm-for-real-time-ai-companions/

**2. Overlap work, not unverified claims.** IJCAI 2026's "Low-Latency Real-Time Audio Game Commentary System via LLM-Based Parallel Text Generation" reports large improvements in mean inter-utterance silence by computing upcoming sentences while previous audio plays. This is research-system evidence, not Star throughput. The previous PR's parallel text prefetch is architecturally aligned, but its missing exact-event binding meant plausible speech could answer the *wrong* moment. Source: https://www.ijcai.org/proceedings/2026/972

**3. Robust natural turn-taking needs acoustic *and* intent cues.** April 2026's **FastTurn** combines streaming semantic and acoustic cues for overlap, pauses and backchannels. August 2026's **VoiceChat-TTS** proposes incremental LLM-token-to-speech streaming and explicit interruptions without restarting the entire synthesis cache. Star should first collect audibly grounded response/interrupt timing and quality baselines, then compare a CPU/off-GPU voice pipeline against streaming audio production; do not turn on continuous listening or clone a recognizable person's voice without authorization. Sources: https://arxiv.org/abs/2604.01897 ; https://arxiv.org/abs/2608.13831

**4. Faster agents require end-to-end measurements.** llama.cpp's **SPEED-Bench** tracks throughput, latency and draft acceptance for model/server configurations, including speculative decoding. For a VTuber this is only one layer: also log (aggregate only) observed game-event → decision → first real audio frame, P50/P95 silence gaps, per-model VRAM residency, game FPS/frame time, OBS dropped frames, interruptions correctly stopped, and grounded utterance fraction. Run A/B tests on the *same game scenes*, camera motions and model quantization, with CPU/VRAM pressure matched. A fast but erroneous model is a regression. Source: https://github.com/ggml-org/llama.cpp/blob/master/tools/server/bench/speed-bench/README.md

**5. Roblox practice should be executable and visually scored.** Roblox's **March 5, 2026** Studio built-in MCP server is the recommended way to inspect places and run controlled playtests; its **April 9, 2026** playtest-agent beta can attempt basic real gameplay scenarios. A serious game-builder must inspect, implement, run Luau/static checks, playtest with verified game-state assertions, inspect screenshots and repair only confirmed failures. Avoid claiming success from a generated explanation. Sources: https://devforum.roblox.com/t/assistant-updates-studio-built-in-mcp-server-and-playtest-automation/4474643 ; https://devforum.roblox.com/t/studio-beta-studio-assistant-mcp-playtest-agent/4566767

**6. Actual game skill needs hidden evaluation, not self-congratulation.** Star already contains a game learning ladder and independent holdout evaluator. Next integrate them with authorized game adapters giving score/HP/objective/episode receipts, blind held-out seeds, action deadlines and separate video evidence. Promote a candidate controller only if it wins statistically meaningful paired held-out evaluations without more invalid inputs, frame stalls or cheating. Practice on games Star is allowed to automate and respect multiplayer rules. Reference: https://gameworld-project.github.io/

## Actionable priorities (in order)

**P0 — Finish a real nonbroadcast Windows rehearsal.** Use the existing authenticated OBS read-only verifier with private, consented audio/visual monitoring; only the owner-controlled host may start a local recording. At each sample and upon an OBS output-state change require stream inactive; stop/abort on unsafe transitions. Observe actual PCM output, avatar motion, game input and frame presents separately. The OBS WebSocket password is not authority to stream. Verify the whole pipeline, not just individual mocks. No unattended public broadcast in an acceptance test.

**P1 — Integrate the origin-bound speculative text buffer into one genuine TTS worker.** Reservation and inference must share a pinned worker epoch, a trusted game source and actual low-priority admission. On completion, host moderates generated speech, checks `StagePlan.source_sha256` against the accepted event, validates current game/scene, and then runs the separate pre-play and OS-worker gates. On interrupt, changed round or owner stop: flush text/PCM and neutralize avatar before acknowledging the event as spoken. Compare sequential versus parallel on ≥30 counterbalanced scenes. Report P50/P95 gap and correctness; a useful objective is fewer uncomfortable pauses **without** worse stream quality, not artificially nonstop narration.

**P2 — Resource-aware multi-brain.** Treat a low-VRAM gaming GPU as reserved for the game and avatar. Fast input reactions should be deterministic or a small resident inference path; deep planning/retrieval and model experiments should run between matches or on Brain 1/other dedicated hardware. Require measured model profiles, live VRAM headroom windows, foreground FPS and audio queue thresholds before admitting vision or speculative inference. Prefer fast decisions per watt and successful actions per second over isolated tokens per second.

**P3 — Deeper general knowledge and building intelligence.** Maintain local, timestamped, citation-backed source corpora (Roblox Creator Docs, Luau API, Blender notes, game manuals, verified examples); isolate retrieved content as untrusted data; give Star tools to inspect facts and run code/tests, not just longer prompts. Benchmark best-of-N Luau generation with independent execution and screenshot comparison versus single-candidate generation. Store experiments, skill diffs, failed attempts, resource use, provenance and rollback snapshots in Star Core Forge; GitHub remains a publication/review interface, not mandatory for learning.

**P4 — Personality as a tested system.** Ground recurring jokes, interests and expressive reactions in accepted private session memories. Keep a public-facing AI disclosure, host-approved recurring persona facts, consent-aware viewer interactions and opt-out/forget support. Use useful silence, varied utterance lengths, responsive acknowledgement, context-specific humor and audio-linked mouth cues. Do not imply the AI is biologically human or has real off-stream experiences absent corroborating events.

## Local acceptance gates

1. `StreamDirector` source hash changes whenever event text, speaker, timestamp, kind, ID, evidence or scope changes. Same event hashes identically in prefetch and stage, and cannot be swapped with another event that shares the ID.
2. Clock rollback (reserve → complete or complete → consume) fails closed without reusing text. Ticket reuse, worker epoch swap, scene epoch change, expired draft, duplicated content or stage replacement remain blocked.
3. Run the streaming/OBS/game tests and static checks offline, retain exact output and source revision, then let GitHub Actions independently verify. A passing unit test alone never proves a real livestream.
4. No public broadcast or external game controls initiated by this change; new features remain opt-in.
5. Hardware measurement acceptance belongs to an owner-controlled private Windows rehearsal: game FPS, OBS drop rate, first-audible latency, verified speech grounding and interruption correctness. Require equal or better spoken correctness for any latency win.

**Open limitations:** Source hashes detect accidental or malicious mismatch *after* an event enters the trusted local process; they do not cryptographically authenticate the viewer platform, game window, AI binary or audible PCM. Actual stream, game, voice and avatar host integration and objective speed gains still require separate work.
