# STAR AI: paired game-skill evidence, two-timescale gaming, and VTuber systems
**Research snapshot:** 2026-11-02. **Status:** code change and synthetic offline regression tests; not a real game win, speedup, model-training result, live stream, or validation of a Windows recording.

## Reproduced qualification weakness and correction
Star's existing `compare_game_skill` accepted a candidate with **six better held-out cases, one slightly worse case, and seventeen ties**. Improvements spanned multiple maps and raised aggregate progress without tripping any severe-regression checks. Yet under an independent, symmetric paired-direction null, the one-sided exact sign-test tail is **P(X >= 6 | n=7, p=0.5) = 8/128 = 0.0625**, above the 0.05 screening threshold. Before correction the candidate was marked `eligible=True`; after correction it remains **ineligible** with `paired_gain_not_statistically_supported`. A control with seven improvements, one small decline and sixteen ties has **P = 9/256 = 0.03515625** and remains eligible for **manual investigation**. Verified synthetic tests, not live gameplay.

Implementation in `star/game_skill_gate.py` adds a deterministic exact paired sign test and read-only `paired_sign_pvalue` to `GameSkillVerdict`. Non-tied gameplay-direction changes take priority when game outcomes or progress improve; latency direction is used for speed-only claims. Ambiguous near-ties do not increase evidence. Existing independent requirements still apply: identical paired held-out seeds, cross-map coverage, no practice/holdout leakage, retention of previous wins, bounded per-map/global regressions, repeated gain across maps, and unchanged prohibition on auto-deployment.

**Limitations:** A p-value is NOT proof of learning. Exact sign-test calibration presumes independent, preregistered paired cases and a preselected comparison. Correlated game seeds, adaptive stopping, multiple trials to find a favorable result, fabricated host attestations, or repeated inspection of holdouts invalidate a literal 5% false-discovery interpretation. This gate is supplemental, deliberately advisory, and must never be used to claim improved neural intelligence or autonomously promote weights. Require fresh hidden held-outs, game-server or Studio executable checks, and a separate human review for promotion.

## Ranked engineering program

### 1. Two-timescale real-time gaming (highest intelligence return)
- **During play:** sample a timestamped scene, check focus, version, episode, and telemetry; route to an optimized fast model only if its host-observed p95 + dispatch reserve fits a scene deadline; use the existing immutable lease, fresh scene recheck, issued one-shot action permit and key-release confirmation. Drop stale answers. Avoid slow teacher calls in the live loop.
- **Between attempts:** freeze a failure replay, have a stronger teacher propose concise reusable strategies (not executable game commands), trial them in a private sandbox, and compare paired independent held-outs with `compare_game_skill` and `game_transfer_eval`. Reject wins that depend on seen maps/seeds, frame delay regressions, or fragile single-map luck. Keep a visible scorecard of wins, progress, p95 action latency, crash rate and per-map deltas.
- **Curriculum:** start with timing and camera control, then pathfinding, objectives, combat/aim under permitted rules, cooperative play, and unseen mechanics. Generate harder tasks only after a held-out improvement; do not confuse training attempts with independent qualification. Game rules/anti-cheat still apply.
- **Evidence:** RealtimeBench evaluates 180 live-clock tasks; its authors' teacher-student approach improved their *study's* student average progress from 13.51 to 24.19 after two rounds. It does not demonstrate a measured gain for Star. https://arxiv.org/abs/2610.20665 (2026-10-14).

### 2. Faster inference while preserving playable FPS
- **Profile under actual workload:** record first response token, p50/p95 completed tokens/sec, request tail, VRAM free/peak, CPU load, game frame-time p99, audio end-to-end first audible PCM, dropped OBS frames, and concurrent request slot count. Baseline and candidate must be measured in randomized matched game sessions on the same scene version.
- **Benchmark controlled options:** `llama.cpp` prompt-prefix caching, continuous batching, quantization/context choices and speculative decoding, including draft-model vs n-gram alternatives. Compare same prompts and per-category results with its **SPEED-Bench** runner; speculative draft acceptance varies significantly by task and can hurt latency. https://github.com/ggml-org/llama.cpp/blob/master/tools/server/bench/speed-bench/README.md
- **8 GiB reality:** do not claim all 9B models can always fit once KV cache, OBS, game textures and avatar are resident. The real host must reserve VRAM before model load, shrink context or reroute to CPU/another computer when memory is constrained; never evict game/OBS resources for speculative inference. Prior 3060 Ti readings were snapshots and not sustained measurements of available budget.
- **Process architecture:** keep low-latency game capture/input/voice/OBS adapters isolated from background teacher models. Python orchestrator + Rust/C++ for demonstrably hot paths; measure before rewriting working components. No network keys in telemetry or game traces.

### 3. Real Roblox game development rather than attractive screenshots
- Inspect the target place hierarchy, scripts, dependencies, dimensions, lights and collision groups **before editing**. Generate 4-8 alternatives only when independent compilation/sandbox checks can select a winner. Reject mismatched mesh sizes, duplicate props, missing walls, erroneous attachment points and obstruction before taking an in-editor screenshot.
- Use a staged verifier: syntax/type/lint, static dependency graph, geometry/collision audit, Studio edit/undo, multiplayer simulated clients, VirtualInput UI interaction, and a pixel/scene-quality pass. Each stage has an explicit rollback and evidence artifact. Test seed, Roblox API version and place commit are part of the receipt.
- Roblox's **OpenGameEval** paper and harness cover 84 stateful Studio tasks with executable scene and simulated-play checks. Its findings favor inspection before editing; its published scores are not Star's. https://github.com/Roblox/open-game-eval and https://arxiv.org/abs/2610.02563 (2026-10-01).
- Studio testing tools: https://github.com/Roblox/creator-docs/blob/main/content/en-us/studio/testing-modes.md

### 4. Humanlike *presentation* as an AI VTuber
- **Listen naturally:** keep voice-activity uncertainty and locally measured end-of-turn gaps separate; choose turns by the cost of interrupting versus awkward delay. Preserve authenticated owner barge-in, viewer chat moderation, echo cancellation and a non-speaking state under uncertain audio.
- **Perform like a character:** state-aware gaze/blinks, idle breathing, expression transitions, laughter/sighs tied to actual generated speech or game events, subtle hair movement, scene-appropriate curiosity and silence, and recognizable Star/Astro/Amber interactions. Attach expressions and lip-sync to **consumed audio samples**, not speculative TTS completion timestamps.
- **Remember truthfully:** scene- and episode-scoped, approved recollection of actual recorded game moments; keep an immutable distinction between a verified game win, a prediction, and an illustrative story. A humanlike character can show personality, preferences, humor and rapport without falsely claiming to be biologically human or asserting unverified emotions/experiences.
- **Connect the real software:** local VTube Studio API uses trusted plugin authorization and custom parameters; OBS WebSocket 5.x supports supervised, password-protected nonbroadcast control. Neither should be exposed unauthenticated to viewers. https://github.com/DenchiSoft/VTubeStudio/blob/master/README.md ; https://github.com/obsproject/obs-websocket
- **Speech candidate:** Kyutai Pocket TTS is a CPU-oriented audio-streaming option; assess pronunciation, expressivity, audible TTFA, p95 stall rate and CPU pressure against existing speech options before selection. Its upstream repository notes thread-safety limitations. https://github.com/kyutai-labs/pocket-tts
- **Acceptance:** do a private 20-30-minute game+voice+avatar+OBS rehearsal, record no viewer private content, and audit interruption rate, true audible timing, mouth/gaze synchronicity, game FPS and model latency. Do not broadcast without explicit owner approval.

### 5. General knowledge, autonomous learning and persistent character
- Route fact questions to grounded local evidence first, or opt-in fresh web research for time-sensitive facts, with citations, confidence and expiry. Keep private knowledge isolated from public streaming replies. Do not treat an embedding search hit or self-written note as independently verified truth.
- Store a small persistent self-model (identity, goals, current interests, capabilities, uncertainty) plus provenance-tagged memories; maintain durable lessons only after independent tests. Give the character ongoing hobbies, drawing/game-building challenges, social conversation goals and self-scheduled study, while keeping spending/publication and other high-risk actions behind appropriate approval gates.
- Implement evaluation lanes for game execution, coding, physical scene quality, UI/animation taste, voice turn-taking, retrieval truthfulness, and infrastructure recovery. Promote improvements by a Pareto-style rule: no unacceptable regressions in safety, FPS or quality for a latency win.

## Practical acceptance gates (future, not yet measured)
| Lane | Measurement to capture | Gate before rollout |
| --- | --- | --- |
| Live fast model | p50/p95 inference delay, missed deadlines, 1%-low game FPS | No stale action; no measurable game-frame degradation; latency improvement repeated over paired sessions |
| Learning transfer | matched unseen wins/progress, per-map differences, paired sign p | No practice/holdout contamination; p < .05 advisory screen; independent replay and human review |
| Stream presence | interruption/false cutoff, speech p95 TTFA, audio frame stalls | Better turn-taking without regressions in audible delivery |
| Avatar | consumed PCM alignment, expression/gaze lag, mouth mismatch | No clock fast-forward; sustained stable nonbroadcast playback |
| Roblox creator | executable Studio pass, multiplayer join/leave, collision/prop audit | No missing geometry or regression in preexisting tests |
| General knowledge | grounded factual answer coverage, hallucination/PII leakage rate | Public-safe citation and source provenance; deny outdated/unapproved memory |
