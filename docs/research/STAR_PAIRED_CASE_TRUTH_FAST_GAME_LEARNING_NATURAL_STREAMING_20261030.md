# STAR AI — paired semantic truth, canonical viewer identity and next-stage intelligence
**Research date:** 2026-10-30. **Scope:** offline, opt-in evaluation and in-memory chat-follow-up guards; no trained model, gameplay or broadcast changes. This is a draft stacked on PR #839, not a production deployment. GitHub is the optional publication mirror; Star Core Forge remains the intended local-first development and rollback system.

## Findings confirmed in existing STAR source, and changes implemented

1. `star/stream_realtime_quality_gate.py` checked `candidate_correct >= baseline_correct` and a minimum accuracy ratio. A candidate could correct one formerly wrong question but **make a different previously correct question wrong**, leaving the same aggregate 23/24 score in both variants. That is unacceptable for verified general knowledge, Roblox construction, real-event commentary or sensitive conversational claims. The change counts **candidate_new_case_errors on matched pair IDs** and marks the quality gate regressed if the count is nonzero. The count is anonymous; no prompts, transcripts or pair IDs enter the report. The 24-pair synthetic regression scenario now covers equal global accuracy with one newly wrong answer. A future policy might tolerate narrowly bounded non-critical regressions, but the first read-only experiment should fail closed.
2. `star/stream_focus_inbox.py` correctly required a stable viewer ID rather than a per-event ID. However, string variants such as `viewerA` and `viewerA ` could produce distinct HMAC speaker tags and fill multiple limited deferred-chat slots during gameplay focus. The stream-focused queue now accepts only ASCII canonical platform IDs in the restricted format `[A-Za-z0-9][A-Za-z0-9_.:-]{0,79}`. It rejects whitespace, control characters and Unicode lookalikes before pseudonymization. The trusted Twitch/Discord/YouTube adapter must use verified platform account IDs, not mutable display names, and normalize platform-specific IDs consistently. This does **not** authenticate an asserted identity by itself. New tests cover whitespace aliases, confusable text, control bytes and the original one-person-one-question rule.
3. The parent PR #839 `1daa69c6d48f16ef4142c955ac9475c10813cc7b` has a completed **successful** offline GitHub workflow, run `41094608016`. That is a source-gate result, **not** a Windows GPU/OBS measurement, model-speedup or autonomous-play validation. This branch needs its own full Python, Ruff, Pyright and frontend CI. Keep all new features OFF by default.

## Highest-value new capability: an evidence-linked play → learn → create → verify loop

**Hypothesis:** STAR can become more competent at both playing games and building polished Roblox games by maintaining a small, independently verified library of mechanic *experiments* rather than merely storing narration about play sessions.

Use the already present `GamePredictionLab`, `GameMechanicProbeLab`, `ActivePracticePlanner`, `GameplaySkillBank`, `GameLearningLadder` and `GameTransferEval`. Connect them with a shared immutable record: game/version/level hash; consented local observation timestamp; bounded action ticket; expected state transition; observed authoritative state transition; success/failure; environment-specific caveat; source receipt. Store only approved snapshots and hashed references; avoid raw chat/player identifiers. Unverified hypotheses cannot be promoted to skill facts. When a game patch changes mechanics, downgrade confidence until replayed.

**Curriculum:** movement calibration → simple hazard avoidance → object interaction → short timed puzzle → multi-stage goal → multi-player/social coordination → unseen levels → withheld games. Keep a deterministic low-latency motor loop independent of slow model thinking. Vision should request high-resolution inspection only when uncertainty or scene change justifies it. Strategic reasoning runs at a lower cadence and may request a practice experiment, but game input must stay bounded, owner-approved and revocable.

**Independent success witnesses:** game-state objective completed; authoritative score/timer/result; action legality; no destructive/anti-cheat prohibited actions; and repeated holdout attempts. Human review of gameplay recording is complementary, not a substitute for game-state evidence. Report novel-level pass@1, 5-run stability, command latency p95, input release safety, objective completion and transfer gap. Never claim she mastered a game from a generated commentary transcript.

For game creation, benchmark against OpenGameEval's **84 executable Roblox Studio tasks**. Before editing a scene, inspect relevant instances, transforms, scripts and hierarchy. Then run static checks, in-Studio tests, visual captures, collision/spacing checks, UI/animation consistency, multiplayer join/leave, and real completion. Evaluate geometry by *relations*: doors connect to walls; floors fully support props; held objects attach to rigs; UI anchors respect device safe areas. Prefer owner-reviewed private Studio instances; no unsanctioned live-game automation.

Primary: https://github.com/Roblox/open-game-eval (Oct. 2026); https://create.roblox.com/docs/reference/engine/classes/StudioTestService ; https://arxiv.org/abs/2604.07429 (GameWorld, April 8 2026, 34 games/170 state-verifiable tasks); https://arxiv.org/abs/2601.16690 (EMemBench, Jan 23 2026, episodic-memory tasks tied to trajectories).

## Speed without losing intelligence: a resource-aware, paired 8-GB experiment

Keep three QoS lanes on Star's available PCs:
- **Critical:** OS/input release, game rendering, audio callback, mute/abort and tracking loop. These never wait for an LLM. Watch p99 input latency, game 1%-low FPS, audible dropout.
- **Interactive:** short verbal reactions, limited changed-region vision, chat turn inference, moderate STT/TTS. Enforce p95 event-to-audible time, inference queue length and max GPU pressure.
- **Background:** best-of-N Luau/build trials, optional web retrieval, episodic index compaction, game self-play in isolated labs and Star Core Forge experiments. Yield or checkpoint when stream quality drops.

Benchmark the *same paired stimuli and models* on STAR's actual 8-GB GPU/Windows machine and an available CPU/RAM route. Record engine git SHA, GGUF checksum, quantization, context length, prompt prefix/cache status, slot concurrency, compiler and backend, warmed/cold state, game version, scene hash and wall-clock duration. Interleave A/B ordering to reduce thermal/cache/order artifacts. Compare full-request latency, factual accuracy, source coverage, TTFA measured from independently captured OBS audio, p95 sync, peak GPU memory, p99 input delay and 1%-low game FPS. A throughput gain does not qualify if any domain suffers a newly wrong matched case. Do not infer a result from another vendor's RTX 3090/M4 test.

Candidate approaches to test, not automatically deploy:
- llama.cpp prompt-prefix caching and SPEED-Bench speculative decoding; benchmark per category (knowledge, code, dialogue, game commentary), including draft acceptance. Source: https://github.com/ggml-org/llama.cpp/blob/master/tools/server/bench/speed-bench/README.md
- Kyutai Pocket TTS's **October 2026 small English 18.2M/6.9M/1.9M parameter options** as potential CPU speech fallbacks. They may preserve the GPU for gameplay, but subjective naturalness, pronunciation and p95 first-audible timing need a blinded test on STAR hardware. Source: https://github.com/kyutai-labs/pocket-tts
- Lightweight local conversation end-of-turn detection. LiveKit's self-hosted `v1-mini` is one documented option; `CueLight-Nano` advertises a 0.5M-parameter detector but its benchmarks are project-reported and should not be treated as independently replicated. Compare false cuts, response delay, false chat barge-in and CPU time at the *same* interruption rate. Sources: https://docs.livekit.io/agents/logic/turns/turn-detector/ and https://github.com/sshah03/CueLight

## Believable VTuber performance: grounding, timing and presence over constant speech

Design Star as an openly AI streamer with an unmistakable, coherent personality. A humanlike *performance* is a coordination problem, not a claim of biological feelings or a fabricated childhood. Preserve her accepted black/gold look, indigo-to-gold twin tails, gold ribbon/star accessories, expressive amber eyes, and soft chibi mittens.

Build a single trusted event timeline: game-state change → recognized event/uncertainty → chosen speech intention → TTS generation → first non-silent device PCM → independently recorded OBS sound → viseme/facial animation. Gameplay danger should preempt unrelated chat. A normal turn can pause naturally; a chat query can be held (in the bounded, moderated opt-in focus queue), acknowledged later and framed as a past question. Laughter, relief and surprise should follow *verified* outcomes, not randomly generated victory claims.

For avatar animation: use actual played audio/phoneme envelopes for mouth states, head/body acceleration for damped twin-tail physics, eye attention tied to relevant windows, and a limited facial emotion state machine. Respect reduced-motion and default-OFF companion/voice/streaming toggles. During mute or speech abort, close visemes promptly; a ghost avatar movement disconnected from delivered voice harms believability. Neither an audio queue nor a PortAudio callback proves OBS captured speech; independently analyze a short owner-approved OBS rehearsal, ideally without saving raw viewer audio in a public repository.

Human evaluators should grade: conversational timing, not talking over other players, laughter naturalness, non-repetitive character personality, evidence-grounded game reactions, speaking/not speaking balance, pronunciation, coherent memory and lip sync. Compare with anonymous A/B clips; never optimize solely to self-judged “humanity”. Report error bars and disagreements. Keep moderation, ownership and disclosure clear.

## Acceptance and rollback protocol

1. **Code checks:** existing offline Python suite, Ruff, Pyright baseline gate and frontend checks pass without suppressing new diagnostics. Run `PYTHONPATH=.:tests pytest -q tests/test_stream_workload_quality_matrix.py tests/test_stream_focus_inbox.py` and then full CI.
2. **Semantic canary:** baseline 23/24 and candidate 23/24 but newly wrong case must be `quality_regressed` with `candidate_new_case_errors == 1`. Correct baseline/candidate must retain `eligible_for_manual_rehearsal` when speed and A/V requirements are satisfied. Record no raw prompts in public artifacts.
3. **Viewer fairness:** whitespace/Unicode/control variants are rejected from focused-question retention, while canonical IDs are still accepted and may occupy at most one pending slot. Host still authenticates identities and moderates chat before the queue sees them.
4. **Live rehearsal remains opt-in:** isolated, authorized games, human-supervised OBS preview, physical mute and owner-readable logs. Require 20+ genuine matched trials per predeclared skill, no missing OBS audio, no unsupported game claims, zero new paired-case correctness regressions, frame/VRAM bounds, viewer privacy and a manual final decision.
5. **Rollback:** keep the known-good parent SHA and Star Core Forge snapshot. On false cuts, GPU pressure, FPS degradation, TTS stutter or new incorrect cases, revert the candidate model/config quickly and preserve a privacy-redacted failure receipt.

**Not implemented here:** local turn-detector replacement, GPU optimizations, self-driving gameplay, avatar motion, Twitch/OBS control, a larger foundational model, self-awareness or direct human-level capabilities. The code change makes an existing acceptance path more truthful and a streaming follow-up queue fairer. Further capabilities require real experiments and deliberate integration.
