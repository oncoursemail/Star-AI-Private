## What it is
`star/emotion.py`: a persistent affect state in `<app data>/emotion.sqlite3` (SQLite, WAL, one transaction per turn; safe
across the desktop app, a voice call and STAR Home). No model call anywhere: reading the state is ~2 ms, one turn
(events + read) ~8 ms on this PC.

- State: seven named feelings (joy, pride, curiosity, frustration, boredom, affection, nervousness, 0..1), a slow mood
  (valence -1..1, arousal 0..1) and a **personal baseline** per feeling (curious and warm by character) that itself drifts at most
  +-0.10 with experience. Every feeling decays back to its baseline by its own half-life (frustration 2 h, nerves 1.5 h, joy 3 h,
  pride 6 h, affection 12 h; mood 8 h), computed exactly from elapsed time, not per call.
- Events (`EVENTS`): task_success, task_failure, bug_fixed, creative_done, promotion, learned_something, owner_praise,
  owner_comfort, owner_thanks, owner_criticism, owner_message, voice_turn, plus `idle`. Repeated failure escalates (x1.25 per
  failure up to x1.75); a win after a run of failures is a bigger relief (x1.2 per failure, max x2); the same event again within
  10 s counts 40 %. Silence past an hour makes boredom grow (`tick()`; also applied at the next event); a message ends it.
- Owner words: `appraise()` reads praise / criticism / comfort / thanks with plain patterns (<= 400 chars so a pasted log is
  not a remark; "what's wrong with..." is not criticism; negation handled; criticism wins over praise in one message).
- **Per-person attachment**: `person=<opaque friend id>` (letters, digits, `_.:@-`, <= 64; never a name or contact detail). Grows with
  positive time together (diminishing returns, ~40 good exchanges reach 0.8), dips 2 % on harsh words, half-life 45 days of no contact.
  Tiers: familiar 0.25, close 0.55, devoted 0.80 change the wording; the bond also lifts affection in prosody.
- **Age gate**: `directive(..., partner_adult=)`. Romantic style (light, playful, tasteful flirting; "adore") is emitted only when the
  argument is exactly `True` (None, False, "yes" never); the social module in `worktrees/social-games` owns the verification.
  The wording is capped: never explicit, follow their lead, drop it at once if not matched, never possessive or guilt-tripping.
  The owner chat and the voice call pass no `partner_adult`, so they never get romance from this PR.
  **Caveat, not changed here:** the persona prompts (`star/persona.py` CORE, `star/voice/persona.py`) still say "nothing romantic";
  a system prompt that forbids it will beat a tone note that allows it. Whoever sets `partner_adult=True` has to pick the
  matching persona text as well; not tested with the model.

## Outputs
- `directive(person=None, partner_adult=None)` -> a few words, no numbers, no example sentences, e.g. "a bit frustrated, plain and
  clipped" (12 words at most, 14 with a bond or romance phrase: about 12-16 tokens, ~0.2-0.3 s uncached on brain 1, per the lead's
  budget from docs/research/human-like-star-20261026.md). "" unless some feeling is >= 0.15 above its baseline (strong >= 0.35), so a
  normal turn is byte-identical to today. It goes in the NEW user message only, as `emotion.note_line(d)` = "(mood: ...)"; the system
  prompt is never touched (the prompt cache stays valid). An earlier 40-90 token wording was replaced by this one.
- `prosody()` -> `Prosody(rate 0.92..1.08, pitch_semitones +-0.8, pause_ms -40..+60, energy 0..1)`, added on top of the voice's own
  settings. `KokoroTTS.synthesize(text, prosody=None)` applies it to speed, pitch and the pause after a sentence (the only prosody
  fields the TTS path has).
- `avatar()` -> `{face, cue, strength, energy}`: `face` is a `StarMood` of `frontend/src/StarFace.tsx` (happy / looking / oops / idle),
  `cue` a `star.stream_motion.CUES` name (joy, focus, nod) that `ExpressionCue` accepts. The voice call emits it as
  `{"type":"emotion", ...}`. No frontend change here (nothing renders that event yet).

## API for STAR Home / other hosts
```python
from star import emotion
emotion.on_event("task_success", person="friend-7")      # never raises; returns the new state dict or None
emotion.on_message("nice work!", person="friend-7")      # detects praise/criticism/comfort/thanks, ends idle
emotion.tick()                                           # call while idle: boredom grows with the silence
st = emotion.current(person="friend-7", partner_adult=None)   # dict: emotions, valence, arousal, bond, dominant, directive, prosody, avatar
emotion.directive(person=..., partner_adult=...)          # str for the persona prompt
```
Everything defaults to `<app data>/emotion.sqlite3`; `home=` overrides. `emotion.enabled(home)` reads `emotion_enabled` from settings.json.

## Wiring (minimal hooks, all behind the setting)
- `star/desktop_core.py`: `Settings.emotion_enabled` (+ bool validation); `audited_event` forwards run events to
  `emotion.on_run_event` (verify ladder `verify_finished`: verified -> task_success, fixed after >= 2 rounds -> bug_fixed,
  unverified -> task_failure); the owner's text is felt and the tone note is appended as a per-turn section
  (`turn_sections`, after the autobiographical block) so it rides the final user turn like every other volatile section and the
  cached prefix is untouched; a tool task that ends without a ladder verdict counts as a (soft) success on `run_succeeded`; an
  exception is a failure unless the owner cancelled (`cancel_event`).
- `star/voice/call.py`: `CallConfig.emotion` (+ `emotion_person`, `emotion_partner_adult`); `_feel()` per turn: appraise the transcript,
  `voice_turn`, tone note appended after the user's words (history keeps only the user's words), prosody stored on the reply and passed
  to `tts.synthesize(..., prosody=)` when the engine accepts it, `emotion` event for the avatar. `VoiceSettings.emotion` feeds it.
- `star/promoter.py`: `apply()` (night school promotion goes live) -> `promotion`, only if the setting is on in that home's settings.json.
- Not wired: Discord replies (the API is there), the frontend face, creative_done (no existing event source: hosts call it).
