# Metallic metric value correction

The stable Metallic Control time-series store accepted infinite floats and booleans. A reproduced in-memory sample made `Store.series()` contain `Infinity` and a boolean become a numeric `1.0`; the existing API encoder then emitted nonstandard JSON. An integer too large for float conversion also raised instead of allowing valid readings in that sample to proceed. Python documents the distinction between its permissive default and [strict JSON numeric encoding](https://docs.python.org/3.12/library/json.html#basic-usage).

The small correction is confined to `metallic/metallic/control/store.py`. Numeric validation happens before the write transaction: booleans, nonfinite values and overflowing integer conversions are ignored. Finite integers/floats, including zero, negative readings and existing rounding, retain their behavior. An invalid reading cannot replace a valid reading at the same timestamp. Legacy nonfinite chart values and overflowing aggregate results render as JSON `null`, preserving stored history rather than inventing a measurement or deleting data.

`python scripts/verify_metallic_metric_values.py` passed **54 offline assertions**. These exercise the actual API encoder with strict JSON decoding, valid/invalid mixed samples, same-timestamp preservation, subsequent valid writes, restart, legacy raw/minute/ten-minute data, finite aggregates and aggregate overflow. Only temporary SQLite files are used; no HTTP socket, native target or account is accessed. The existing store/API/collector subset passed **22 tests**. Ruff and the scoped whitespace check passed. Harness tests and evaluation files were not edited.

This change covers time-series metric values, not every stored JSON document, request-timing field or timestamp. It does not change authentication, policy, collectors, the launcher UI or the active Claude launcher worktrees. All edits for this fix were made in the isolated checkout; root reviews and commits the patch.
