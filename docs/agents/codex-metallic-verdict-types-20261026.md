# Metallic verdict adapter type validation

`metallic/metallic/checks.py::check_eval` coerced `allowed` with `bool()` and `exit_code` with `int()`. Temporary fake verdict files reproduced incorrect passes for `allowed="false"`, `exit_code=false`, `exit_code="0"` and `exit_code=0.8`. Non-object JSON or other malformed fields could also raise instead of returning a check result.

The adapter now requires a JSON object with an exact boolean `allowed` and an exact integer `exit_code` (booleans are excluded). Only `allowed is True` plus integer zero allows the adapter check. Wrong shapes, missing fields and wrong field types return a static malformed-verdict failure with `blocking=True`; malformed field contents are not echoed. Canonical allow/deny behavior is preserved. Existing missing-file/JSON-decode, report-only, unconfigured and unaffected-path behavior remains unchanged.

This is an owner-directed, separately reviewed integration-adapter correction. It does not change STAR's grader, fixtures, scoring, thresholds, stored baselines, gate configuration or feature activation. The legitimate producer already emits the required boolean/integer types. The file is outside the configured protected-closure patterns, but that absence is not treated as authorization to change evaluation policy. The broad open integration PR #514 includes these modules; the focused Metallic PR #685 does not touch `checks.py`. No existing feature work was reset or overwritten.

Verification: `python scripts/verify_metallic_verdict_types.py` passed **60 fake-file checks**, including exact types, malformed object shapes, static diagnostics, extra producer fields, both file-lookup paths, report-only/blocking modes and the built-in dispatcher. The script forbids subprocess execution around adapter/dispatcher checks. The existing `metallic/tests/test_metallic_check.py` suite passed **17 tests**. Ruff and the scoped diff check passed. Harness tests were read/run without edits. No actual evaluation command, grader, queue, model, native target, account action or promotion was run for this patch.

Type validation does **not** authenticate an artifact, establish that a paired session ran, or bind a verdict to a source tree. The existing adapter still trusts its operator-supplied canonical verdict file. A passing fake canonical file in this verifier is proof of routing compatibility, not an authentic grade, quality improvement or permission to enable a feature. Independent review and root-controlled integration remain required.
