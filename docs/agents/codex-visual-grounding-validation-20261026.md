# Visual grounding guard review

Reviewed the current changes in `star/computer/grounding.py`, `settings.py`, `__main__.py` and `agent.py`, and reran `python scripts/verify_visual_grounding_safety.py`: **71 synthetic checks passed**. The verifier uses fake endpoints, frames, windows and input sinks, plus temporary configuration files. It does not contact a model, capture a private desktop, send native input or access accounts. These checks establish the exercised contracts, not native grounding accuracy.

Calibration retains the existing six-button gate: all six recognized points must lie inside their intended 120×40 buttons, with center-distance mean **≤12 px** and maximum **≤20 px**. Missing answers cannot become fabricated zero points. An uncalibrated `auto` grounder refuses runtime lookup before requesting inference. Explicit coordinate formats remain supported; this does not make a manually selected format evidence of successful calibration. Both native 2B candidates still failed the unchanged precision gate and remain disabled; see the [native record](codex-native-pc-validation-20261026.md).

Coordinate parsing accepts recognized, unambiguous point/box structures and known wrappers. It rejects incidental numbers in prose, ambiguous coordinate fields, booleans, nonfinite values, malformed/reversed boxes and oversized coordinate responses. Runtime lookup checks coordinate ranges before conversion, including box corners, instead of clamping invalid results into plausible clicks.

Visual targeting binds the result to the observed foreground HWND, PID, executable, rectangle and title, the eye/capture source, image dimensions and RGB pixels. Frame-backed checks require a capture produced after the foreground check and within the configured age limit; a synchronous fallback grabs after the check. Wrong foreground, cropped/offset images, stale frames, replaced capture sources or changed pixels refuse the target. The checks run after inference and again immediately before mouse-down through a wrapper that preserves the original sink guard and cleanup methods. A known pre-press refusal reports zero accepted input, avoiding an unrelated cleanup release. The original sink is restored afterward.

The model's point becomes a one-pixel target, removing the former invented 48×48 target and Computer's random aiming offset for visual points. Default desktop Hands disable deliberate misses; explicit custom profiles remain supported, and gameplay defaults are unchanged. This is point-preservation behavior, not proof that the model chose the correct control or that a native click achieved the intended outcome.

The calibration CLI permits inspecting a configured candidate while `grounder.kind=none`. A passing run saves its explicit format and measurement report while preserving the existing kind and unrelated settings. Snapshot comparisons reject intervening owner edits; the locked update exercises rollback on STOP and simulated write failure. Preview sends no request or save. STOP is checked between requests and before acceptance/save; an in-flight synchronous HTTP request must return or time out before cancellation is observed. This does not claim crash-proof storage or recovery when rollback itself cannot write.

Exact matching compares the full captured desktop. Animations, blinking carets, clocks or other changing pixels can therefore refuse an otherwise usable target; no tolerance or automatic retry was added. These checks are not an OS-level lock on an application. They do not establish Discord identity, a selected contact/channel, account ownership, permission to message someone, or successful communication. Existing authorization and input-receipt checks remain necessary. No evaluation fixtures or quality thresholds were changed by this review.
