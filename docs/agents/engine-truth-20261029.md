# engine-truth-20261029: game-engine API truth in the router and the verifier (claude, board #357)

Wave docs/agents/WAVE-20261029-STAR-SMART.md (lane engine-truth, wave LITHA-AGENT). Worktree `worktrees/engine-truth`, branch
`star/engine-truth-20261029` (from origin/star/next b1498bb9). Pattern: the one that took Minecraft from 5 to 23/48
(docs/agents/mc-data-20261029.md): exact facts from the real source in front of the question + a verifier that knows the
real API and gives exact suggestions to the fix pass.

## What it is

| engine | truth source | facts note (router) | verifier (star-polyglot, container side) |
|---|---|---|---|
| Godot 4.x | the engine's own `godot --dump-extension-api` (4.7.2): every signature in the note is filled from it | core + 14 topics | the real engine parses the file (existing) + members of the real classes as fix candidates (existing); unchanged |
| Unity 6 | Unity's scripting-reference search index (46,015 pages; 2022.3 index for the diff); text is curated, `build/verify_unity_facts.py` checks 78 names exist and 6 renamed ones are gone | core + 10 topics | Roslyn + Unity stubs (now with `Awaitable`, `destroyCancellationToken`, `UnityEngine.Pool`), index member check (existing), new: obsolete table (FindObjectOf*, Cinemachine 2 names, UnityWebRequest flags ...), CS0104 (`Random`), CS1503 GameObject vs component, near-miss type names; several files in one block (usings hoisted) |
| Unreal 5.x | none available (Epic's source needs an Epic account): curated from the public docs, NOT compiler-checked | core + 8 topics | structural rules that UHT / the compiler enforce (no engine headers, so no compile): GENERATED_BODY, `.generated.h` last, AddDynamic handlers = UFUNCTION with the delegate's exact signature, DECLARE_*_Params counts, RPC `_Implementation`/void, replication macros, Enhanced Input handler signatures, class prefixes, CreateDefaultSubobject outside the constructor, `new` of UObjects, missing `Super::`, private BlueprintReadWrite |
| LOVE 11.x | LOVE 11.5 itself (apt `love`, LuaJIT 2.1) under Xvfb: names of `love.*` and the LuaJIT standard tables dumped from the running engine; signatures from the love-api index | core + 9 topics | luacheck against that std (invented functions, undefined variables), LOVE rules (0-255 colours, key/mouse names), and a SMOKE RUN of the answer in the real engine (120 frames, scripted keys/mouse): runtime errors with line numbers |
| plain Lua 5.4 | the Lua 5.4 reference manual (library names; sha256 of the page in the table below) | core only | luacheck against that std (string.split, table.find, math.clamp, Roblox globals), `:split()`-style methods, ipairs(io.lines()), io.read formats, match captures indexed like a table, `%d` with a float, 64-bit overflow literals |

Router: `server/mesh/engine/facts.py` (+ `facts_data.py`, data in `engine/data/*.json` generated by `engine/build/*`). One note
per question (`(Facts for Litha, ...)`), keyword-picked topics, <= 3,000 characters (~750 tokens: the 4 GB nodes have a
4,096-token context), header `X-Mesh-Engine: godot core+t0+t3 2559`. It replaces the generic polyglot note for these
engines (polyglot's hook skips a turn that carries "(Facts for Litha"); Unity questions had no note before. Opt-out per
request `mesh_engine: false` (the verifier's fix call sends it), per config `engine_facts: false`.

Verifier: `server/mesh/polyglot/engine.py` (loaded by `runner.py` by path, helpers injected), LOVE/Lua data in
`server/mesh/polyglot/data/`, new checker language `love` (core.py routes blocks with `love.*` calls there; a Lua block of a
question that asks for "plain Lua"/"Lua 5.4" and is not Roblox goes to the plain-Lua checker; before, every untagged Lua
block was checked as Roblox Luau).

  names/types and enum members were kept (`build/love_index.lua`); the wiki prose is dropped. LOVE 11.5-1build1 and Xvfb from
  the Ubuntu 24.04 archive, installed into star-polyglot by `deploy.sh engine` (NIC added for the install, removed after).
- Godot 4.7.2 (the container's engine, GitHub digest checked by the polyglot lane), Unity index fetched 2026-10-29 by the
  polyglot lane (docs.unity3d.com).
- Ubuntu's `lua5.4` is built with LUA_COMPAT_MATHLIB (math.pow/atan2/cosh/log10 exist there but NOT in a standard Lua 5.4):
  that is why the Lua names come from the manual, not from the binary.
- LOVE 11.5 still has love.filesystem.exists/isFile/isDirectory/getSize (deprecated, gone in 12): the facts say so; they are
  not flagged. `love.graphics.setColor(255, 0, 0)` is clamped to (1, 0, 0): colours above 1 are flagged, the message says so.

## Rejected / not shipped, and why
- Facts for plain Lua (judged -1 pass / -0.17 score, hidden tests 1/18 -> 0/18, more checker flags), LOVE (hidden 0/12 both, assertion fraction 0.17 ->
  0.13), Unreal (judged +0.00 although the structural errors went 3 -> 0 of 9) and Godot (judged +0.39 on the new tasks but hidden tests flat:
  3/18 -> 2/18): code stays in `engine/facts_data.py`, switched off by `engine_facts_families`. Bar used: judged score +0.25 on the new tasks AND
  no loss on hidden tests / API errors; only Unity passes it.
- Facts text inside the verifier's fix prompt (`FIXFACTS` in evalrun2): coded in the eval script, not measured, not shipped.
- A fact-check agent found five definite errors in the first facts text before the final run (two-argument `math.atan` in LuaJIT silently
  ignores the second argument; `love.data.encode` is not a serializer; Awake would discard Inspector arrays; double ObjectPool Release only
  throws in the Editor; bare `schedule` needs `root.`; GAS interface owner; Lua version wording); all were fixed and the Unity/LOVE answers
  regenerated. Lesson: a facts note is a liability when a sentence is wrong; every placeholder signature is generated, the prose is reviewed.

## Honest caveats
- In-sample parts: the Unity facts were written after I had read the polyglot lane's judge reasons for its six Unity tasks (pool Release type, UnityEvent vs
  Action, NavMesh line of sight, ...). Five of the Unity gains are on exactly those tasks. On the six unseen Unity tasks the judged score
  rose +0.94 (4 up / 0 down) but strict passes stayed 1 -> 1. Four Lua pitfall rules (match captures indexed like a table, io.read formats,
  ipairs(io.lines), 64-bit decimal literals) and the Unreal RPC-return rule were added after reading baseline failures of these tasks:
  their effect on those tasks is in-sample; their precision was checked on the references and the older corpus.
- One judged sample per arm and task; the hidden-test tasks have two. Judged passes are single digits: read the score deltas, not the pass counts.
- Unreal has no engine here (Epic's source needs an account): the structural rules are the ones UHT and the compiler enforce, but nothing is compiled.
- Unity: no Unity runs; checks are Roslyn + stubs + the docs index. LOVE object methods (`img:getWidth()`) are not checked, only `love.*` functions.
- Other lanes' load: the shared router returned 502/503 for stretches; arms were generated interleaved, one request at a time.

## Also fixed on the way (existing false alarms of the live checker)
- GDScript: a `preload("res://...")` of a scene/image that is not in the check folder was reported as an error and stopped the engine's analysis at
  that line (hiding real errors): `preload` -> `load` before the check.
- C# (Unity): valid `async Awaitable` code gave CS0161/CS0103 (no Awaitable / destroyCancellationToken in the stubs); several files in one
  block (`// File: A.cs` ... with their own usings) gave CS1529.
- Lua: every untagged Lua block was checked as Roblox Luau, so `string.split` / `table.find` in a plain-Lua answer passed.
- LOVE: stand-ins for assets the answer loads (images, sounds, fonts), so a missing file is not reported as a bug of the code.
