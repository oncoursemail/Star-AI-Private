# star-home-20261026: STAR Home (her own PC: host agent, her own loop, one-script setup)

Branch `star/star-home-20261026` (worktree `worktrees/star-home`, from origin/star/next 13da2b5b). Issue #613 req. 1
and the owner's 2026-10-26 direction: on her own PC STAR is admin and decides for herself, no permission prompts.

## What is built
- `star/home/control.py`: data folder `C:\ProgramData\STAR\home` (STAR_HOME_DIR overrides), owner STOP file,
  append-only redacted `actions.jsonl`, `config.json` defaults, global hotkey Ctrl+Alt+Shift+F12 -> STOP.
- `star/home/host.py`: `Executor.do(action, args)`: shell (PowerShell/cmd), winget_install, read/write/list files,
  screenshot, click/move/type_text/key (pyautogui), launch (apps/files/URLs), ask_owner (writes approvals.jsonl, runs
  nothing). Logs start + done/refused/error. Refuses: everything while STOP exists; any path/command touching the
  control folder; remote-control commands (ssh/scp/RDP/PS remoting/psexec/net use), so STAR Home never reaches the
  owner's other machines (the brain is reached only by star/home/brain.py over HTTP with the key file). dry_run logs
  and runs nothing.
- `star/home/life.py`: interests with weights she changes (tool set_interest; each session nudges x1.1 verified /
  x0.95 not, clamp 0.1-5), persistent goals, `history.jsonl` with claimed vs verified outcome, novelty (falls per
  session in 24 h, halves right after one), bounds (sessions_per_day, pause_minutes). Seeds: game_making, drawing,
  music, research, practice, play_games, chat_with_friends.
- `star/home/brain.py`: bounded tool loop against `/v1/chat/completions` (max_steps, session_minutes). Verified =
  she claimed success, at least one non-read action succeeded, every artifact she named exists and is non-empty,
  and not dry run. star/agent.py was not reused: its registry is the Roblox Studio allowlist (star/policy.py).
- `star/home/activities.py`: registry. Built-in brain sessions for the 5 creative interests. Plug-ins: `star.games`,
  `star.social`, `star.senses` may define `register_home_activities(registry)` and call
  `registry.register(name, interest, run, about, gpu_mb=..., needs_brain=...)`; `run(ctx) -> {ok, verified,
  summary, evidence, failures?, goal_done?}`. A broken plug-in is recorded in `plugin_errors`, others keep running.
  play_games / chat_with_friends are picked only once a plug-in registers them. GPU game mode: while a process in
  config `game_processes` runs, an activity with `gpu_mb` is eligible only if free VRAM - gpu_mb >= `game_reserve_mb`
  (default 5000 of the 8 GB RTX 4060).
- `star/home/loop.py`: one cycle = stop check -> budget -> eligible activities -> pick -> run -> history -> failures to
  the curiosity queue (`<home>\curiosity.jsonl`: failed_verification per unverified session, tool_failure per failed
  action) -> practice resolves the item it studied. Emotion hook: `star.emotion.on_event({...})` if installed.
- `star/home/__main__.py`: `python -m star.home run|once|status|stop|resume|interests|weight|log|check` (--dry-run).
- `installer/star-home/setup.cmd` (self-elevates) -> `setup.ps1`: Python 3.12 via winget if missing, copies `star\`
  to `C:\STAR\home\app`, venv + pillow/pyautogui, config.json (asks brain address and dry-run Y/n), scheduled task
  "STAR Home" (at her logon, RunLevel Highest, Interactive = her desktop session, restarts), STAR STOP.cmd /
  STAR RESUME.cmd on the desktop, OpenSSH server (LocalSubnet, Private/Domain), asks for the lead's PUBLIC key line
  and writes administrators_authorized_keys (ACL Administrators+SYSTEM, then PasswordAuthentication no), runs
  `star.senses.setup` if present (optional, non-fatal), dry-run self-test, prints computer name, user and IPv4.
  `setup.cmd -Uninstall` removes the task and desktop files. Parse-checked only (not run: needs admin on her PC).

## Owner steps on STAR's PC (once)
1. Make STAR's Windows account an administrator and sign in as her. (Automatic sign-in after restarts is a setup.cmd
   step below; you type her password into Microsoft Autologon's own window, STAR Home never sees it.)
2. Sign in to her Roblox, Minecraft and Discord accounts yourself in their apps/browser on that PC and tick "remember
   me", so the sessions persist. STAR Home never handles passwords: none go into her model, logs or config.
3. Get the code onto the PC: in a browser signed in to GitHub, download the ZIP of branch `star/next` (after this PR
   lands; before that, of `star/star-home-20261026`) from oncoursemail/Star-AI-Private, extract it.
4. Double-click `installer\star-home\setup.cmd`, approve the administrator prompt. It asks:
   - Brain address (Enter to let the lead set it).
   - Dry-run first? Y = actions only logged until the lead flips `"dry_run": false` in
     `C:\ProgramData\STAR\home\config.json`.
   - The lead's public key: on YOUR PC run `type %USERPROFILE%\.ssh\id_ed25519.pub` and paste that one line
     (public part only). Enter skips; run setup.cmd again later to add it.
   - Automatic sign-in after restarts? Y downloads Microsoft Sysinternals Autologon (signature checked) and opens it:
     type her password, press Enable. It also turns off sleep on AC power. In the BIOS set "Restore on AC power loss"
     to On so the PC starts again after a power cut.
   - No lock screen / no admin prompts? Y turns off sign-in on wake and the secure screen saver, and lets her admin
     account elevate without the Yes/No prompt (UAC stays on). She never needs her password; her model never knows it.
5. Send the lead the last lines it prints (`ssh <user>@<address>`).
Stop her at any time: desktop `STAR STOP.cmd`, or Ctrl+Alt+Shift+F12. `STAR RESUME.cmd` resumes.

## Lead steps after setup
`scp %USERPROFILE%\.star\server_api_key <user>@<addr>:.star/server_api_key` (key never printed), set brain_url in
config.json if not given, `python -m star.home check` (one tiny brain request; not while a sealed eval runs), read
`python -m star.home log`, then set dry_run false.

## Not done
- Not run on the real PC (address unknown); setup.ps1 only parse-checked. Brain path not called live (brain 1 eval).
- Owner credential helper (Credential Manager -> typed by a non-LLM helper): NOT built in this branch; logins rely on
  sessions the owner signs into once. Left for the lead to decide.
- PC curiosity file is not shipped to night school on brain 1 yet (needs a push over the brain API).
- Screenshots are not sent to the model (config `vision` reserved); no foreground-window/UI tree reader yet.
- Real-world gates are prompt + tool-level (no purchase/post/account tools; ask_owner queue); GUI actions could still
  reach a website, so the gate is not enforced in code for GUI clicks.
- The STOP guard is path/text based; a deliberately obfuscated shell command could evade it. An owner-only ACL on
  the control folder would need STAR to run as a non-admin, which the owner did not want.
