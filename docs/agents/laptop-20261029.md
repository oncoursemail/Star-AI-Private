## 2. Added: busy guard (this branch)
`server/knowledge/laptop/busy_guard.py` (+ `install-busy-guard.cmd`, `run-gpu-worker.cmd` now in the repo, both supervisors
wait on a PAUSE file, `rerank_worker.py --pause-file`). Runs on the laptop in the owner's logon session (a session-0 task cannot
see windows) as hidden below-normal task `STAR laptop busy guard`, folder `starai\busy-guard\`.
- Probes: the Litha mesh node's (`server/mesh/node/node_agent.py`, copied next to it): known game with a window
  (Valorant, Fortnite, Rocket League, Marvel Rivals added to the node's list: Roblox player/Studio, Minecraft, VRChat, Steam
  games), OBS/Streamlabs/XSplit/VR running, a full-screen program in front, `FAKE_BUSY` file. Extra: other programs' GPU load
  from the Windows "GPU Engine" counters (sum over processes not under `starai`, >= 40% on 3 looks = 6 s). Poll 2 s.
- On busy: writes `starai\PAUSE`, kills the llama router (`taskkill /T`, port 8090). The supervisors wait while PAUSE exists
  (log "PAUSE file found, waiting"). The rerank worker (a session-0 S4U process that the guard's token may NOT terminate:
  first try failed with access denied) polls PAUSE every 0.5 s and exits by itself. Result: ports closed, VRAM 0, brain 1 takes over.
- Resume: after 120 s without a busy look PAUSE is deleted and the supervisors restart the workers. On start the guard
  deletes a stale PAUSE. If the guard dies, PAUSE stays (safe for the owner) and the guard task restarts it (1 min, 3 tries).
- Bug found and fixed on the way: `if exist PAUSE (if not defined X (...) & ... & goto loop)` skips the rest when the inner
  `if` is false (cmd chains `&` into the inner if), so the supervisor restarted the server every 3 s while paused. Now a
  multi-line block. Visible in the first test run.

## 5. How to stop and undo (on the laptop, or `ssh laptop "<cmd>"` from the PC)
- Give the GPU back right now and keep it free: `type nul > %USERPROFILE%\Documents\starai\busy-guard\FAKE_BUSY`
  (the guard pauses both workers within about 2 s and holds that while the file exists); `del` it to release (the workers
  are back 120 s later). This is also the harmless test switch.
- Stop the workers for good (no guard involved): `type nul > ...\gpu-worker\STOP` and `type nul > ...\rerank-worker\STOP`,
  then kill them (`laptop-ctl.cmd stop gpu` does the first part for llama; for the reranker kill the python on :8092 from an
  admin shell: `for /f "tokens=5" %p in ('netstat -ano ^| findstr ":8092 .*LISTENING"') do taskkill /PID %p /T /F`).
  Start again: delete the STOP files, `schtasks /run /tn "STAR laptop GPU worker"` and `... rerank worker`.
- Stop only the guard: `schtasks /end /tn "STAR laptop busy guard"` (PAUSE, if present, stays: `del ...\PAUSE`).
  Remove it: `schtasks /delete /tn "STAR laptop busy guard" /f` then `del ...\PAUSE`; the supervisors then run as before
  (backups of the old ones: `gpu-worker\run-gpu-worker.cmd.20261029.bak`, `rerank-worker\run-rerank-worker.cmd.20261029.bak`).
- Brain-1 side is unchanged. To drop the laptop reranker there: remove
  `star-knowledge.service.d/laptop-rerank.conf` in container `starai` and restart `star-knowledge` (laptop-rerank-20261021.md).
