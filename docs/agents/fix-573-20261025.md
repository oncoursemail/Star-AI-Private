# fix-573 (2026-10-25, Claude): generated image "file missing", quick model refusing pictures

Issue #573. PR #574 (merged into star/next 10-23) already added: note-first/atomic `_save`, `_on_disk` guard,
`MAKE_ME` in `frontend/src/imageIntent.ts`, ComfyUI in `Documents/starai/media`. This pass re-traced both bugs on
star/next 53ef0485.

## (a) "file missing"
- Only source of the text: `star/chat_images.py` `chat_image()` (`not path.is_file()`), called per stored assistant row by
  `star/react_shell.py` `_chat_view()` on every state refresh. The row is stored by `_run_image` only after
  `generate_chat_image` returned, so on star/next the reference cannot run ahead of the file.
- Not reproducible from code: tested a junction as `generated-images`, a relative home, the full bridge path with a fake
  ComfyUI then `_chat_view` (test added, passes before and after). The owner's 2.0.0 build had the old `_save`
  (PNG first, note second): a note that fails to write left a picture without a .json (the 210119 file).
- Remaining hole fixed: `image_gen._save` wrote the note first and let a failing note (OSError, unserializable value)
  raise, losing a picture that was already made. The note is now best effort; the picture is still saved atomically.
- If it recurs: the message does not say which path it looked at; check `%APPDATA%\STAR\generated-images` vs the name in
  the stored row (`conversations.sqlite3`, `STAR_GENERATED_IMAGE:<name>`).

## (b) quick model refuses pictures
- Detection exists only in the frontend (`imageIntent.ts`, narrow wording). Anything it misses ("Generate a real cow with
  no weird legs", "create a cartoon cow", agent mode, ...) goes to the text route, which has no picture tool, so the quick
  model says "I can't create or show images" (`react_shell._run_chat` stored that answer as is).
- Fix: `chat_images.refused_to_make_picture(prompt, answer)` (short refusal + prompt starting with a make/draw/show verb
  and naming something to draw) and a hand-over in `_run_chat` before the answer is stored: same turn, same user row,
  `_run_image(..., turn_user_id=user_id)`. Skipped with attachments, documents, song lookup, or Settings "Create images
  straight from chat" off; "Can you create images?" stays a text answer.
- Not done: a real image tool for the agent loop; widening the TS regex (too many text requests share the verbs).
