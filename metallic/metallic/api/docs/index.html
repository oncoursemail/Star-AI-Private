Metallic API v1.0.0

One API for the Metallic launcher, website, game servers and (later) outside developers. Internal preview: outside developer access comes later. The machine-readable document is /v1/openapi.json (OpenAPI 3.1).

Metallic API v1 sits on top of Metallic accounts. Signed-in calls use a Metallic sign-in token (the launcher's access token) or a scoped token made from it with POST /v1/oauth/token. Game servers use server keys (msk_...) with their own scopes and rate limits. Minors' data is private by default: other parties never receive a minor's username or display name, and scoped tokens for minors can only read the minor's own profile.

Errors always look like {"ok": false, "error": "code", "text": "plain words"}. A 429 carries Retry-After (seconds). Every response carries RateLimit-Limit and RateLimit-Remaining for the bucket that was charged.

Authentication

Send Authorization: Bearer <token>. Three kinds of token:

TokenWho holds itScopes
Metallic sign-in token (JWT)The launcher and other first-party appsThe launcher's Metallic access token (first-party: every user scope; owner/admin also get keys:admin and webhooks:manage), or a scoped mtk_ token from POST /v1/oauth/token that carries only its granted scopes.
Scoped token mtk_…Apps acting for a playerOnly what was granted at POST /v1/oauth/token; at most 15 minutes.
Server key msk_…Game servers and backendsServer-to-server key for game servers and backends. Keep it on the server: in Roblox store it as an HttpService secret and never send it to a client. Each key has scopes, a games list and its own rate limit.
curl -X POST https://HOST:8476/v1/oauth/token -H "Content-Type: application/json" \
  -d '{"subject_token": "<sign-in token>", "scope": "friends:read presence:read"}'

Rate limits

CallerPer minuteBurstCounted per
anonymous6030client IP
user12060account

Some endpoints have their own tighter bucket (token exchange: 10 per minute per IP). Over the limit: 429 with Retry-After. Every response carries RateLimit-Limit and RateLimit-Remaining.

Minors' privacy

Players under 18 are private by default. Accounts already limits who sees their presence and who may send them requests; on top of that the API never hands a minor's username or display name to a server key or webhook (only an opaque account id with minor: true), and scoped tokens for minors can only hold profile:read.

Errors

{"ok": false, "error": "insufficient_scope", "text": "This token lacks the scope presence:write.", "scope": "presence:write"}

401 no or bad token, 403 wrong credential kind, missing scope or a privacy rule, 404 unknown thing, 429 slow down, 502 accounts unreachable, 503 a release channel failed verification.

Webhooks

Create one with POST /v1/webhooks; the whsec_… secret is shown once. Each delivery is a POST with a JSON envelope {"id", "type", "created", "data"} and these headers:

Metallic-Event: player.joined
Metallic-Delivery: dlv_…
Metallic-Signature: t=1793000000,v1=<hex HMAC-SHA256(secret, "1793000000." + raw body)>

Check the signature on the raw body, refuse ones older than 5 minutes, answer any 2xx quickly, and de-duplicate on id: failed deliveries are retried after 10 s, 1 min, 5 min, 30 min and 2 h, then marked failed. The delivery log is at GET /v1/webhooks/{id}/deliveries. Events: player.joined, player.left, release.published, friend.added, ping.

# Python
from metallic_api import verify_webhook
ok = verify_webhook(secret, request.headers["Metallic-Signature"], raw_body)

SDKs

Thin clients generated from this document live in metallic/sdk/: python/metallic_api.py (standard library), js/metallic-api.mjs (browsers and Node 18+), luau/MetallicApi.luau (Roblox servers; the key comes from HttpService:GetSecret and the module refuses to run on a client). POST/v1/oauth/token

Make a scoped token from a sign-in token

Public. Rate: 10/min.

OAuth 2.0 token exchange (RFC 8693 style). subject_token is a Metallic sign-in token. The new token carries only the requested scopes, lives at most 15 minutes and never longer than the sign-in token, and stops working when the player signs out. Minors may only request profile:read. Admin scopes are never delegated.
